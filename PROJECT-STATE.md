## 1. MACHINE AND MEMORY BASELINE

THE INITIAL/MINIMUM MACHINE IS A PDP-6 WITH 32K WORDS OF CORE.  PDP-10
BACKENDS MAY ADD MACHINE-SPECIFIC FACILITIES WITHOUT RAISING THAT BASELINE.
THE GENERIC VM/MM BOUNDARY MUST REMAIN REPLACEABLE BY A MACHINE-SPECIFIC PAGER.

THE HARD PERMANENT KERNEL LIMIT IS ADDRESSING BELOW 040000, INCLUDING FIXED
RESIDENT AND IRREDUCIBLE MRES/SCRATCH PACKAGES.  KCC IS THE ACCEPTANCE BUILD.
SHRINKAGE SWEEPS ARE REQUIRED ONLY WHEN THE CONFIGURED HARD LIMIT IS ACTUALLY
EXCEEDED.

CURRENT VERIFIED FULL MEASUREMENT:

    KCORE               9882 WORDS
    CTY MRES              62 WORDS
    DRM MRES             117 WORDS
    D6FS MRES           2336 WORDS
    DTFS/TSFS MRES      2161 WORDS
    LOGSTORE MRES          91 WORDS
    KCORE+MRES         16217 WORDS
    PERMANENT_LAST      037610
    SINGLE_ROOT FREE       119 WORD ADDRESSES
    MULTI_LAST           037661

THE 32K LOWMEM PROFILE IS A SEPARATE TRANSIENT-KINIT ACCEPTANCE BUILD AND BOOTS
THROUGH THE NORMAL LOGIN/DSH PATH.

## 2. BOOT AND ROOT POLICY

STAGE1 SELECTS THE ROOT CONTROLLER CLASS.  KINIT DISCOVERS AND VALIDATES THE
ROOT SET AND FILESYSTEM, INSTALLS ONLY THE REQUIRED PERMANENT PACKAGES, LOADS
`/SYSTEM/INIT`, AND RECLAIMS BOOT-ONLY STATE.

SUPPORTED V0.9 ROOT PATHS INCLUDE DSK/D6FS, DRM/D6FS, AND DTC/TSFS.  AUTO ROOT
POLICY PREFERS DSK, THEN DECTAPE, THEN DRM.  THE SHARED D6LZ36 TOKEN CORE AT
000060 IS USED BY COMPRESSED BOOT/EXEC PATHS WITHOUT A SECOND RESIDENT DECODER.

HARDWARE/ROOT DISCOVERY STAYS IN STAGE1/KINIT.  ADMINISTRATIVE POLICY SUCH AS
ADDITIONAL MOUNTS, SWAP/LOGSTORE SELECTION, AND OPTIONAL RAMFS BELONGS IN INIT
AND `/CONFIG`.

## 3. PROCESS, VM, IPC, AND TTY

THE PDP-6 VM BACKEND USES CONTIGUOUS USER EXTENTS, RELOCATION/PROTECTION,
PROCESS COMPACTION, AND WHOLE-IMAGE SWAPPING.  CLEAN RECLAIMABLE FILESYSTEM
CACHE IS DROPPED BEFORE PROCESS SWAP.

PROCESS GROUPS, SESSIONS, DOMAINS, CONTROLLING TERMINALS, FOREGROUND GROUPS,
STOP/CONTINUE, CHILD STATE REPORTING, DESCRIPTOR I/O, PIPES/FIFOS, AND NATIVE
PROCESS EVENTS ARE IMPLEMENTED.  THE MINIMAL TTY LINE DISCIPLINE PROVIDES
COOKED INPUT, ECHO, ERASE/KILL/EOF, OPTIONAL FOREGROUND CTRL-C/CTRL-Z, AND RAW
MODE FOR USERSPACE EDITORS/SHELLS.

RUNTIME LOADABLE/UNLOADABLE/RELOCATABLE MODULE MOVEMENT IS NOT RESIDENT IN
V0.9.  THAT WORK IS EXPLICITLY DEFERRED UNTIL AFTER USERSPACE OVERLAYS.

## 4. VFS AND NAMESPACE

VFS OWNS PATH WALKING, MOUNT CROSSING, FILESYSTEM DISPATCH, DESCRIPTORS,
CREDENTIAL/MODE CHECKING, AND COMMON FILE/FIFO OPERATIONS.

MONITORFS IS THE ONLY KERNEL-STATE FILESYSTEM:

    /MONITOR/PROCESSES
    /MONITOR/DOMAINS
    /MONITOR/DEVICES
    /PROC                  ALIAS OF /MONITOR/PROCESSES
    /DEV/NAME              DEVICE I/O ENDPOINT VIEW

`/DEVICE` AND `/DOMAIN` ARE NOT EXPOSED.  DO NOT RECREATE BROAD SYSCTL/DEVIO
COMPATIBILITY ABIS; ADD THIN NATIVE OPERATIONS ONLY FOR DEMONSTRATED NEEDS.

## 5. D6FS, BLOCKSET, AND BADMAP

D6FS IS THE NATIVE WRITABLE FILESYSTEM.  CURRENT V0.9 SUPPORT INCLUDES
MULTI-MOUNT, DSK/DRM BACKING, REMOUNT, CRASH-RECOVERY SELECTION, UID/GID/MODE,
MTIME, SEEK, CHOWN, RMDIR, A SMALL RECLAIMABLE WRITE-THROUGH BLOCK CACHE, SWAP
RESERVATION, LOGSTORE RESERVATION, AND COMMON BADMAP TRANSLATION.

BLOCKSET PROVIDES GENERIC LOGICAL-TO-PHYSICAL MAPPING FOR MULTI-MEMBER SETS.
SINGLE-MEMBER ROOTS BYPASS ITS MRES.  SEMANTIC OWNERSHIP OF SWAP/LOGSTORE DOES
NOT LIVE IN BLOCKSET.

BADMAP IS THE SINGLE OPTIONAL PERSISTENT PHYSICAL-EXCEPTION MAPPER SHARED BY
DSK270 AND DRM236.  CLEAN MEDIA INSTALL NO BADMAP PACKAGE.  ONLINE RETIREMENT
AFTER RECOVERED DATA IS DEFERRED MAINTENANCE WORK.

## 6. DSK270 AND DRM236 SCHEDULING

DSK270 USES ITS BOUNDED PER-UNIT CYLINDER ELEVATOR.  DRM236 USES A MINIMAL
ONE-PENDING FIFO.  DRM SCHEDULING MAKES NO ROTATIONAL OR TIMING ASSUMPTIONS,
BECAUSE THE CURRENT SIMULATOR DOES NOT PROVIDE USEFUL ROTATIONAL DATA.

THIS IS THE V0.9 STORAGE-SCHEDULER CLOSURE.  CROSS-SPINDLE OR ROTATIONAL
POLICIES MAY BE REVISITED ONLY WITH MEASURABLE BENEFIT ON REAL OR
TIMING-ACCURATE HARDWARE.

## 7. TSFS

TSFS V1 IS A READ-ONLY DECTAPE FILESYSTEM.  `MOUNT.TSFS` PERFORMS TRANSIENT
MEMBER/TABLE/CHECKSUM/EXTENT VALIDATION AND PASSES A COMPACT HANDOFF TO THE
RESIDENT PROVIDER.  LOOKUP, READDIR, STAT, PARENT TRAVERSAL, MULTI-EXTENT AND
CROSS-MEMBER READS ARE IMPLEMENTED.

REGULAR DATA USES 0400-WORD RESTART EXTENTS.  EACH EXTENT IS D6LZ36 WHEN THAT
SAVES DECTAPE BLOCKS AND STORED OTHERWISE; METADATA REMAINS DIRECT.  TSFS MAY
ALSO SERVE AS THE BOOT ROOT.

## 8. LOGSTORE

LOGSTORE V1 IS COMPLETE.  D6FS PERSISTS THE RAW LOGICAL RESERVATION; KINIT
RECOVERS THE RING and publishes the compact runtime state.  THE RESIDENT MRES
PROVIDES STATUS, BOUNDED RAW I/O, COMMIT-LAST APPEND, AND RACE-SAFE WAIT/WAKE
WITHOUT A PERMANENT 128-WORD RECORD BUFFER.

THE ROOT-ONLY LOGCTL TRANSPORT SERVES `/SYSTEM/EXEC/LOGDRAIN`.  LOGDRAIN
IMPLEMENTS NULL, D6FS FILE/ROTATION, SEVERITY-FILTERED CONSOLE, AND MTC
ARCHIVAL SINKS WITH REDUNDANT PERSISTENT DRAIN STATE, LOSS/GAP ACCOUNTING,
EOT/REEL RESUME, AND FINITE-DRAIN FILEMARK.  INIT AND LOGIN PRODUCE NORMAL
OPERATIONAL RECORDS.

## 9. CLOCK AND REAL-TIME MODE

THE STANFORD PHIL PETIT PCLK AT DEVICE 0730 IS THE STANDARD WALL-CLOCK SOURCE.
GETTIME RETURNS UTC TIME36 FOR 2026-01-01 THROUGH 2125-12-31.  THE APR 60 HZ
LINE CLOCK REMAINS THE MONOTONIC SCHEDULER/TIMER CLOCK.

THE MINIMAL SINGLE-OWNER REAL-TIME USER PROCESS MODE AND RT_REQUIRED EXEC
ADMISSION ARE IMPLEMENTED.  HISTORICAL MUSIC SOFTWARE REMAINS USERSPACE; THE
KERNEL FACILITY IS GENERIC.

## 10. NORMAL USERSPACE

NORMAL BOOT IS KINIT -> `/SYSTEM/INIT` -> LOGIN -> CONFIGURED SHELL.  INIT
READS `/CONFIG/INITTAB`; LOGIN USES `/CONFIG/PASSWD`, ESTABLISHES CREDENTIALS,
SESSION/PROCESS-GROUP/TTY STATE, HOME/ENVIRONMENT, AND EXECUTES THE CONFIGURED
SHELL.

RUN/EXEC USE THE BOUNDED COUNTED-SIXBIT STARTUP ABI.  NORMAL USERSPACE BUILDS
WITH KCC/DAS WITHOUT LIBGCC.  DSH EXISTS as the initial shell but substantial
DSH implementation remains the next userland phase after the final pre-userland
gate.

## 11. TEST AND ACCEPTANCE POLICY

REAL LOGIN, NOT A BARE DSH PROMPT, IS THE NORMAL SYSTEM REACHABILITY TEST.
IMPORTANT CORRECTNESS CHANGES REQUIRE PERMANENT REGRESSIONS IN THE TESTKIT.
COMPILER OR ASSEMBLER MISCOMPILATIONS TAKE PRIORITY OVER FEATURE WORK.

`MAKE PERMANENT-SIZE` IS A HARD GATE AFTER MATERIAL RESIDENT CHANGES.  EXACT
SIZE VALUES ARE RE-MEASURED CURRENT STATE, NOT STATIC DESIGN CONSTANTS.

## 12. DEFERRED V0.9 NON-GATES

THE FOLLOWING ARE EXPLICITLY NOT PRE-USERLAND V0.9 GATE ITEMS:

- RECOVERY/SINGLE-USER DECTAPE ENVIRONMENT;
- GENERAL USERSPACE OVERLAYS UNTIL REAL WORKING SETS ARE MEASURED;
- LOADABLE/UNLOADABLE/RELOCATABLE RUNTIME MODULES UNTIL AFTER OVERLAYS;
- ONLINE BADMAP RETIREMENT;
- DSK MULTI-SECTOR STREAMING WITHOUT MEASURED BENEFIT;
- DRM ROTATIONAL SCHEDULING WITHOUT REAL/TIMING-ACCURATE DATA;
- GENERAL PAGER BACKENDS BEYOND THE REPLACEABLE VM/MM BOUNDARY.

## 13. CURRENT DEVELOPMENT ORDER

INTERRUPT THIS ORDER ONLY FOR CORRECTNESS OR COMPILER/ASSEMBLER DEFECTS:

1. COMPLETE THE REMAINING BOOT/ROOT MATRIX.  PRODUCTION COMPRESSED BOOT-SOURCE
   INTEGRATION IS GREEN FOR DSK, DRM, DTC, PTR, AND MTC: EACH SOURCE LOADS THE
   FULL `KINIT.D6LZ.WORDS` IMAGE AND REACHES INIT/LOGIN WITH AUTO DSK/D6FS.
   EXPLICIT ROOT-CLASS ACCEPTANCE IS GREEN FOR DSK/D6FS, DRM/D6FS, AND
   DTC/TSFS USING DSK AS AN INDEPENDENT BOOT TRANSPORT.  AUTO PRIORITY IS
   VERIFIED AS DSK -> DTC -> DRM.  COMPLETE THE REMAINING SUPPORTED INDEPENDENT
   BOOT-SOURCE/ROOT-CLASS COMBINATIONS.
2. FINISH LOGIN/LOGOUT/RESPAWN ACCEPTANCE ACROSS ALL REQUIRED ROOT/TERMINAL
   PATHS.  DCS0 IS THE RELIABLE PRIMARY ACCEPTANCE TRANSPORT; CTY INPUT
   INJECTION IS OPTIONAL IF THE SIMULATOR CONSOLE CANNOT DELIVER IT RELIABLY.
3. FINISH INIT + `/CONFIG` POLICY FOR OPTIONAL RAMFS/NONESSENTIAL MOUNTS AND
   SWAP/LOGSTORE SERVICE SELECTION/ACTIVATION.
4. RUN THE COMPLETE PRE-USERLAND ACCEPTANCE MATRIX UNTIL `MAKE REGRESSION` IS
   GREEN FROM START TO FINISH.  LOGIN IS A HARD REACHABILITY GATE; A KERNEL OR
   INIT BANNER ALONE IS NOT ACCEPTANCE.
5. ONLY THEN IMPLEMENT SUBSTANTIAL DSH AGAINST `PDP10-DOC/USER/DSH_DESIGN.MD`.
6. PORT THE MINIMUM CORE USERLAND; THEN PORT/BUILD MAKE, DAS, DLINK, AND DARC.
7. ADD THE PDP-10 CODE-FOLDING UTILITY TO PDP10-TOOLS AND MEASURE ITS RAM
    BENEFIT; ALSO MEASURE REAL NATIVE USERSPACE WORKING SETS.
8. IMPLEMENT USERSPACE OVERLAYS ONLY AFTER NON-OVERLAY PROGRAMS WORK AND THE
    MEASUREMENTS JUSTIFY THE BOUNDARIES.
9. AFTER OVERLAYS, REVISIT LOADABLE/UNLOADABLE/RELOCATABLE RUNTIME MODULES.
10. COMPLETE NATIVE KCC/CPP/LIBC/CRT0/LIBSYS SELF-HOSTING AND THEN A FULL NATIVE
    KERNEL BUILD.
