## 1. HARDWARE BASELINE

DAIMOS TARGETS A PDP-6 WITH 32K WORDS OF CORE AS THE INITIAL/MINIMUM MACHINE.
PDP-10 SUPPORT MUST NOT SILENTLY RAISE THAT BASELINE.

STATE: IMPLEMENTED IN THE CORE DESIGN AND LOW-MEMORY TESTS.  A COMPLETE 32K
INIT -> LOGIN -> DSH ACCEPTANCE RUN MUST REMAIN A RELEASE GATE.

## 2. KERNEL MEMORY BUDGET

THE HARD ARCHITECTURAL KERNEL BUDGET IS BELOW 16K WORDS INCLUDING ALL FIXED
RESIDENT AND IRREDUCIBLE SCRATCH KERNEL MEMORY.  THIS IS THE ONLY ACTIVE FIXED
SIZE LIMIT.  RECLAIMABLE MANAGED-CORE CACHE IS ACCOUNTED SEPARATELY BECAUSE IT
CAN BE RETURNED TO THE GENERAL ALLOCATOR UNDER PRESSURE.

KCC IS THE ACCEPTANCE BUILD.  `MAKE PERMANENT-SIZE` MUST BE RUN AFTER MATERIAL
KERNEL CHANGES AND THE RESULT RECORDED AS A MEASUREMENT, NOT PROMOTED INTO A
SECOND ARCHITECTURAL LIMIT.  GCC MAY BE USED FOR CODE-QUALITY COMPARISON BUT
DOES NOT RELAX THE KCC LIMIT.

STATE: THE OLD SHRINK-PASS TARGETS AND EXACT HISTORICAL SIZE BASELINES ARE NOT
ACTIVE ACCEPTANCE RULES.  KEEP THEM IN GIT HISTORY RATHER THAN COPYING THEM
FORWARD AS CURRENT CLAIMS.  REOPEN SIZE WORK IMMEDIATELY IF THE HARD BELOW-16K
LIMIT, BOOTABILITY, OR 32K MULTIUSER ACCEPTANCE IS THREATENED.

## 3. CURRENT DEVELOPMENT PHASE

DAIMOS HAS REACHED MULTIUSER USERSPACE.  PCLK IS EXPLICITLY ENABLED BY THE
GENERATED SIMH CONFIGURATION, NORMAL USERSPACE BUILDS WITH KCC/DAS WITHOUT
LIBGCC, AND THE BOUNDED VERSIONED RUN/EXEC STARTUP ABI IS IMPLEMENTED.

STATE: ACTIVE.  RUN V2 AND EXEC V1 PASS ARGC/ARGV/ENVP AS AC1/AC2/AC3; INIT
PASSES EACH LOGIN TTY AS NORMAL ARGV[1], AND A NON-COMMITTED AUTO-EXEC PROBE
BOOTED INIT -> DSH THROUGH EXEC REPLACEMENT.  SCRIPTED REAL TELNET ACCEPTANCE
NOW PASSES INIT -> LOGIN -> DSH -> EXIT -> LOGIN ON BOTH DCS0 AND GE0; CTY
INPUT-INJECTION ACCEPTANCE REMAINS OPEN.  A DUP2-EQUIVALENT DESCRIPTOR REPLACEMENT
OPERATION IS IMPLEMENTED AND TARGET-PROBED.  THE MINIMAL TTY LINE DISCIPLINE
AND MODE ABI ARE ALSO IMPLEMENTED.  PROCCTL 030 NOW PROVIDES THE DESCRIPTOR-LEVEL
ISATTY QUERY AND HAS BEEN TARGET-PROBED THROUGH REDIRECTION/DETACH/RESTORE.

## 4. D6FS SWAP AND LOGSTORE RESERVATIONS

EACH D6FS FILESYSTEM MAY CONTAIN ZERO OR ONE SWAP RESERVATION AND ZERO OR ONE
LOGSTORE RESERVATION.  THEY ARE NOT FILES AND HAVE NO ORDINARY FILE I/O OR
NAMESPACE SEMANTICS.  D6FS OWNS THEIR PERSISTENT LOGICAL RESERVATIONS AND
EXCLUDES THE BLOCKS FROM NORMAL ALLOCATION.

VFS DISCOVERS AND REGISTERS THE RESOLVED BACKING LOGICAL RANGE.  ONCE ACTIVE,
SWAP/LOGSTORE I/O BYPASSES FILE I/O AND USES THE LOWER BLOCK/DISKSET FAST PATH.
THE STORAGE-SET LAYER ALONE CHOOSES PHYSICAL DISTRIBUTION AND BAD-MEDIA
MAPPING; DEVICE DRIVERS OWN DEVICE-SPECIFIC SCHEDULING.  LOGICAL RESERVATIONS
ARE CONTIGUOUS EVEN WHEN THEIR PHYSICAL STORAGE IS DISTRIBUTED OR REMAPPED
AROUND BAD MEDIA.

ON SPINNING DISKS, SWAP IS PREFERRED AT THE FAST OUTER EDGE AND LOGSTORE AT THE
INNER EDGE DIRECTLY AFTER THE BOOT AREA.  SIZES AND BOUNDARIES ARE ALIGNED TO
DEVICE-PERFORMANCE GEOMETRY, NOT TO A RAM-SIZE MULTIPLIER.  DRUMSETS HAVE NO
INNER/OUTER RULE.  RESERVATIONS MAY BE CREATED, GROWN, SHRUNK, MOVED, OR
DELETED OFFLINE; MOVEMENT PRESERVES CONTENTS.  PACKFS PROVIDES FREE-RUN
PREPARATION.  MKFS.D6FS ACCEPTS INITIAL SWAP/LOGSTORE SIZES.  FSCK VALIDATES
AND REPAIRS THE RESERVATION/ALLOCATION RELATIONSHIP.  A FILESYSTEM PROVIDING
ACTIVE SWAP OR LOGSTORE CANNOT BE UNMOUNTED.

STATE: DESIGN ACCEPTED, MIGRATION NOT YET IMPLEMENTED.  CURRENT DISKSET
SWAP/LOGSTORE LAYOUT FIELDS AND SEMANTIC ENTRY POINTS MUST MOVE UP INTO
D6FS/VFS.  BAD-MEDIA REMAPPING MUST BE ONE COMMON STORAGE-SET MECHANISM FOR
DISKS AND DRUMS BELOW D6FS, SWAP, AND LOGSTORE; DO NOT DUPLICATE MAPS IN
DSK270/DRM236 OR IN FILESYSTEM CODE.  THE CURRENT DISKSET BOOT DECODER READS
BADMAP LOCATION FIELDS BUT THE RUNTIME DISPATCHER DOES NOT LOAD OR APPLY THEM,
AND BOTH PHYSICAL DRIVERS ONLY REPORT I/O FAILURE.  MULTI-MOUNT D6FS STATE MUST
NOT ASSUME A SINGLE GLOBAL FILESYSTEM.

## 5. DEVELOPMENT PRIORITY

CORRECTNESS REGRESSIONS, ESPECIALLY COMPILER OR ASSEMBLER BUGS, TAKE PRIORITY
OVER NEW FEATURES.  FIX DEFECTS AT THEIR SOURCE; DO NOT ADD WORKAROUNDS.
FEATURE CREEP IS AVOIDED.

STATE: ACTIVE DEVELOPMENT RULE.

## 6. MACHINE-INDEPENDENT KERNEL BOUNDARIES

MACHINE-INDEPENDENT KERNEL POLICY IS SEPARATED FROM PDP-6/PDP-10 MECHANISMS
WHERE THIS DOES NOT COST MEANINGFUL RAM OR TIME.  MACHINE-SPECIFIC FAST PATHS
REMAIN PERMITTED AND IMPORTANT.

STATE: MOSTLY IMPLEMENTED.  THE STORAGE-SET LAYER STILL CONTAINS DSK270-SPECIFIC
ASSUMPTIONS THAT SHOULD MOVE BEHIND THE GENERIC LOGICAL BLOCK/SET BOUNDARY WHEN
THAT AREA IS NEXT REWORKED.

## 7. REPLACEABLE VM/MM BACKEND

GENERIC PROCESS, EXEC, SCHEDULER, VFS, AND OTHER KERNEL CODE MUST NOT DEPEND ON
THE PDP-6 CONTIGUOUS-PHYSICAL-IMAGE REPRESENTATION.  THE PDP-6 VM BACKEND USES
RELOCATION/PROTECTION, COMPACTION, AND WHOLE-IMAGE SWAPPING.  A LATER HARDWARE
PAGER BACKEND MAY REPLACE IT WITHOUT CHANGING THE PROCESS ABI.

STATE: THE BACKEND BOUNDARY AND DIRECT-SLIDE COMPACTOR ARE IMPLEMENTED.  MM
TEMPORARILY EXCLUDES THE SOURCE DESCRIPTOR FROM ITS FIT SEARCH, SO THE SOURCE
RANGE ITSELF PARTICIPATES IN THE DESTINATION PLAN.  MODULES PACK LOW AND PROCESS
IMAGES PACK HIGH; EITHER MAY SLIDE THROUGH AN OVERLAPPING SOURCE/DESTINATION
RANGE WITHOUT ALLOCATING A SECOND IMAGE OR EXTENT DESCRIPTOR.  MODULE RELOCATION,
PROCESS RELOCATION-BASE PUBLICATION, AND THE MM DESCRIPTOR REBASE OCCUR WITH PI
SUPPRESSED.  CLEAN D6FS CACHE RECLAIM NOW PRECEDES COMPACTION, AND PROCESS SWAP
REMAINS THE NEXT RECLAIM STEP.  THE PDP-6 SWAP BACKEND STILL NEEDS TO CONSUME
THE GENERIC VFS-REGISTERED SWAP RANGE WHEN POINT 4 IS MIGRATED.

## 8. ASYNCHRONOUS BLOCK I/O

DISK AND DRUM I/O IS ASYNCHRONOUS FROM THE PROCESS PERSPECTIVE.  PROCESSES WAIT
ON EVENTS WHILE THE CPU REMAINS AVAILABLE.  EARLY-BOOT AND SLOT-0 SWAP POLLING
ARE VALID SPECIAL CASES WHERE NORMAL SLEEPING IS NOT AVAILABLE.

STATE: SUBSTANTIALLY IMPLEMENTED.

## 9. DCT AND CONTROLLER SCHEDULING

MULTIPLE DISKS MAY HAVE OUTSTANDING MECHANICAL ACTIVITY, BUT THE SHARED
CONTROLLER/DCT PATH DOES NOT PROVIDE INDEPENDENT SIMULTANEOUS MEMORY-TRANSFER
STREAMS.  SCHEDULING SHOULD EXPLOIT SEEK/ROTATIONAL OVERLAP BETWEEN SPINDLES
AND THEN SCHEDULE THE SHARED TRANSFER RESOURCE.  DRUMS USE THEIR OWN
GEOMETRY/TIMING POLICY.

STATE: PARTIAL.  SHARED DCT OWNERSHIP AND PER-UNIT QUEUES EXIST, BUT CROSS-
SPINDLE MECHANICAL OVERLAP SELECTION AND DRUM ROTATIONAL SCHEDULING STILL NEED
A DEDICATED SCHEDULER PASS.  DO THIS AFTER THE STORAGE OWNERSHIP CLEANUP.

## 9A. COMMON BAD-MEDIA REMAPPING

DISK AND DRUM STORAGE SETS USE THE SAME STABLE EXCEPTION-MAP MECHANISM.  A V1
PHYSICAL LOCATOR IS 18 BITS: TWO MEMBER BITS PLUS A 16-BIT MEMBER-LOCAL BLOCK
NUMBER.  THIS COVERS ALL FOUR CURRENT DSK270 UNITS (45056 SECTORS EACH) AND
ALL FOUR DRM236 UNITS (8192 BLOCKS EACH).  ONE 36-BIT WORD THEREFORE HOLDS ONE
SOURCE->REPLACEMENT REMAP.  KEEP THE TABLE SORTED AND SMALL; USE A LINEAR
SEARCH FOR THE PDP-6 PROFILE RATHER THAN A RESIDENT FULL-MEDIA BITMAP.

KNOWN DEFECTS SHOULD BE ASSIGNED STABLE SPARES WHEN A STORAGE-SET GENERATION IS
CREATED.  ADDING A REMAP MUST NEVER SHIFT EXISTING LOGICAL BLOCK NUMBERS.
DEVICE-SPECIFIC RETRY, ERROR DECODING, SEEK/ROTATION POLICY, AND RAW ADDRESS
FORMATION REMAIN IN DSK270/DRM236; ONLY THE EXCEPTION TRANSLATION AND PERSISTENT
MAP FORMAT ARE SHARED.  AN UNRECOVERABLE READ STILL REPORTS DATA LOSS; A
REPLACEMENT BLOCK CANNOT RECONSTRUCT CONTENT THAT COULD NOT BE READ.

STATE: DESIGN ACCEPTED, NOT IMPLEMENTED.  IMPLEMENT THE GENERIC STORAGE-SET
MAPPER BEFORE DUPLICATING ANY DISK-ONLY OR DRUM-ONLY BAD-BLOCK FACILITY.

## 10. COMPATIBILITY PERSONALITIES

THE NATIVE DAIMOS ABI AND IMPLEMENTATION ARE AUTHORITATIVE.  ITS/TENEX
PERSONALITIES MAY BE ENABLED FOR TESTING BUT MUST NOT DICTATE NATIVE DESIGN OR
COST NORMAL RESIDENT MEMORY WHEN DISABLED.

STATE: IMPLEMENTED; PRESERVE IT.

## 11. NATIVE INTERFACES FIRST

KERNEL SYSCALLS AND INTERNAL APIS ARE NATIVE DAIMOS FACILITIES.  COMPATIBILITY
LAYERS TRANSLATE ONTO THEM RATHER THAN DEFINING THE NATIVE ABI.

STATE: IMPLEMENTED; PRESERVE IT.

## 12. PROCESS, SESSION, AND JOB CONTROL

PROCESS GROUPS, SESSIONS, CONTROLLING TERMINALS, FOREGROUND/BACKGROUND GROUPS,
STOP/CONTINUE, AND REQUIRED EVENTS ARE NATIVE KERNEL STATE.  DSH MUST USE THEM
FOR PIPELINES, BACKGROUND JOBS, CTRL-Z, BG, FG, WAITING, AND TERMINAL HANDOFF.
NO SESSIONFS IS REQUIRED.

STATE: KERNEL SUPPORT IS LARGELY IMPLEMENTED AND TESTED.  DSH STILL NEEDS
PIPELINES, BACKGROUND JOBS, JOB TABLES, FG/BG, AND FOREGROUND TERMINAL HANDOFF.

## 13. PIPES AND FIFOS

PIPES ARE NATIVE KERNEL IPC OBJECTS.  THE CURRENT IMPLEMENTATION USES A
128-CHARACTER BUFFER, PIPE_BUF=128 ATOMIC WRITES, BLOCKING READERS/WRITERS,
EOF/BROKEN-PIPE HANDLING, DESCRIPTOR INHERITANCE, AND FILESYSTEM-NAMED FIFOS
WITH TRANSIENT STREAM CONTENTS.

STATE: KERNEL IMPLEMENTATION IS ESSENTIALLY COMPLETE.  DSH MUST NOW USE THE
EXISTING PIPE FACILITY FOR PIPELINES; DO NOT REPLACE IT SPECULATIVELY.

## 14. SELF-HOSTING OBJECTIVE

THE PRINCIPAL USERSPACE OBJECTIVE IS A COHERENT SELF-HOSTING ENVIRONMENT:
DSH, MAKE, DAS, KCC, AND THEIR REQUIRED LIBRARIES/UTILITIES.  OPTIONAL FEATURES
MUST NOT DISPLACE THIS PATH.

STATE: EARLY STAGE.  INIT, LOGIN, DSH, LIBC, AND BASIC COMMAND SUPPORT EXIST.

## 15. KCC IS THE MANDATORY DAIMOS C COMPILER

KCC IS THE NORMAL DAIMOS C COMPILER FOR BOTH KERNEL AND USERSPACE.  GCC MAY
REMAIN AS A COMPARISON/REFERENCE COMPILER, BUT IT IS NOT THE NORMAL DAIMOS
BUILD COMPILER.  ANY KCC OR DAS DEFECT EXPOSED BY CONVERSION HAS PRIORITY AND
MUST BE FIXED PROPERLY.

STATE: NORMAL CURRENT USERSPACE NOW BUILDS WITH KCC AND NO LONGER LINKS
LIBGCC.  INIT, LOGIN, DSH, AND THE EXISTING USERSPACE C SOURCES COMPILE AND
ASSEMBLE WITH KCC/DAS; A KCC-BUILT FULL IMAGE BOOTS THROUGH INIT TO LOGIN.
SCRIPTED DCS0/GE0 INIT -> LOGIN -> DSH -> EXIT -> LOGIN ACCEPTANCE PASSES;
CTY INPUT-INJECTION ACCEPTANCE REMAINS OPEN.  RUNNING KCC ITSELF UNDER DAIMOS
IS A LATER SELF-HOSTING MILESTONE.

## 16. NATIVE PROCESS EVENTS

DAIMOS USES A SMALL NATIVE EVENT MECHANISM FOR INTERRUPT, TERMINATION, HANGUP,
STOP/CONTINUE, ALARM, CHILD, BROKEN-PIPE, AND RELATED PROCESS CONTROL.

STATE: SUBSTANTIALLY IMPLEMENTED.  DO NOT ADD A FULL POSIX SIGNAL MODEL UNLESS
REAL USERSPACE REQUIRES SPECIFIC CATCH/IGNORE/MASK SEMANTICS.

## 17. DOMAINS

DOMAINS ARE NATIVE PROCESS-CONTROL/ISOLATION SCOPES DISTINCT FROM SESSIONS,
PROCESS GROUPS, AND CREDENTIALS.  MEMBERSHIP IS INHERITED AND THE KERNEL
PROVIDES EXPLICIT DOMAIN CONTROL/QUERY OPERATIONS.

STATE: IMPLEMENTED.  THE CURRENT DOMAINFS PRESENTATION WILL MOVE INTO
MONITORFS; THE DOMAIN PRIMITIVE REMAINS.

## 18. DESCRIPTOR-BASED USERSPACE I/O

FILES, TERMINALS, PIPES/FIFOS, DEVICES, AND OTHER I/O OBJECTS USE COMMON FILE
DESCRIPTORS SO INHERITANCE, DUPLICATION, REDIRECTION, AND CLOSE SEMANTICS ARE
UNIFORM.

STATE: SUBSTANTIALLY IMPLEMENTED.  ADD SMALL DESCRIPTOR SYSCALLS ONLY WHEN
USERSPACE WORK DEMONSTRATES A NEED.

## 19. MONITORFS AND THE /DEV VIEW

MONITORFS WILL BE THE SINGLE KERNEL-STATE VIRTUAL FILESYSTEM, MOUNTED AT
/MONITOR.  PROCESS, DOMAIN, SESSION, DEVICE STATE, KERNEL STATE, AND SIMILAR
INTROSPECTION/CONTROL LIVE THERE.  THERE IS NO /PROC FILESYSTEM.

/DEV IS AN ALTERNATE VIEW IMPLEMENTED BY THE SAME MONITORFS CODE AND EXPOSES
ONLY DEVICE I/O ENDPOINTS.  DEVICE STATUS/CONFIGURATION/STATISTICS BELONG UNDER
/MONITOR/DEVICES.  THE CURRENT DEVFS, PROCFS, AND DOMAINFS IMPLEMENTATIONS ARE
TO BE CONSOLIDATED, NOT RETAINED AS COMPATIBILITY FILESYSTEMS.

STATE: PARTIALLY IMPLEMENTED.  THE EXTERNAL NAMESPACE FRONT END IS LIVE:
/MONITOR CONTAINS PROC, DOMAIN, AND DEVICES; /DEV CONTAINS ONLY DIRECT DEVICE
I/O ENDPOINTS; AND THE LEGACY ROOT NAMES /DEVICE, /PROC, AND /DOMAIN ARE NO
LONGER EXPOSED.  LOOKUP, READDIR, STAT, GETCWD, PARENT TRAVERSAL, /DEV
ENUMERATION, AND LEGACY-NAME REJECTION ARE TARGET-PROBED.  THE OLD PROCFS, DOMAINFS,
AND DEVFS SOURCE/PROVIDER BACKENDS STILL IMPLEMENT THE LIVE OBJECTS INTERNALLY
AND MUST NOW BE CONSOLIDATED WITHOUT CHANGING THIS EXTERNAL ABI.

## 20. DEMAND-ALLOCATED KERNEL FACILITIES

EXPENSIVE PER-OBJECT STATE SHOULD CONSUME MEMORY ONLY WHILE THE OBJECT EXISTS
WHERE PRACTICAL.  FIXED TABLES ARE USED ONLY WHEN THEY ARE SMALLER/FASTER.

STATE: STRONGLY IMPLEMENTED IN PROCESS, U-AREA, PIPE, VM, AND MM ALLOCATION.
PRESERVE THIS DURING MONITORFS/VFS WORK.

## 21. VFS OWNS NAMESPACE SEMANTICS

PATH WALKING, MOUNT CROSSING, DESCRIPTOR INTEGRATION, AND GENERIC FILESYSTEM
DISPATCH ARE VFS/GENERIC FILE-LAYER RESPONSIBILITIES.  FILESYSTEM PROVIDERS
IMPLEMENT THEIR OBJECTS WITHOUT DUPLICATING PATH SEMANTICS.

STATE: MOSTLY IMPLEMENTED.  THE LEGACY ROOT-NAME SPECIAL CASES ARE GONE.
STATIC /MONITOR NAMESPACE LOOKUP/READDIR SHARE ONE VFS NAME TABLE, AND GETCWD
USES THE NORMAL PARENT-NAME WALK INSTEAD OF SEPARATE PROC/DOMAIN/DEVICE ABSOLUTE
PATH FORMATTERS.  TRANSITIONAL PROVIDER-SPECIFIC OBJECT DISPATCH STILL NEEDS TO
BE FOLDED INTO THE FINAL MONITORFS BACKEND.

## 22. SPECIALIZED STATE FILESYSTEMS ARE REPLACED BY MONITORFS

PROCFS, DOMAINFS, AND THE MONITORING/ADMINISTRATIVE PART OF DEVFS ARE MIGRATED
INTO /MONITOR AND THE REDUNDANT FILESYSTEM IMPLEMENTATIONS ARE REMOVED.

STATE: PARTIALLY IMPLEMENTED.  THE EXTERNAL STATE TREES HAVE MOVED UNDER
/MONITOR AND THE LEGACY ROOT NAMES ARE REMOVED.  THE REDUNDANT INTERNAL
PROCFS/DOMAINFS/DEVFS BACKENDS AND NAMES REMAIN TRANSITIONAL IMPLEMENTATION
DETAILS TO CONSOLIDATE.

## 23. /DEV IS I/O ONLY AND PART OF MONITORFS

/DEV IS NOT A SEPARATE DEVFS.  IT IS A SMALL ALTERNATE MONITORFS VIEW THAT
EXPOSES ONLY OPENABLE DEVICE I/O ENDPOINTS.  THE SAME UNDERLYING DEVICE OBJECTS
ARE OBSERVED/CONTROLLED THROUGH /MONITOR/DEVICES.

STATE: EXTERNALLY IMPLEMENTED.  /DEV ENUMERATES DIRECT I/O ENDPOINTS AND
/MONITOR/DEVICES ENUMERATES DEVICE STATE DIRECTORIES WITHOUT AN IO CHILD.  BOTH
CURRENTLY SHARE THE EXISTING AUTHORITATIVE DEVICE OBJECTS INTERNALLY; BACKEND
SOURCE CONSOLIDATION REMAINS.

## 24. MONITORFS VIEWS LIVE KERNEL STATE

MONITORFS MUST GENERATE VIEWS FROM AUTHORITATIVE KERNEL OBJECTS RATHER THAN
MAINTAINING DUPLICATE PROCESS/DOMAIN/DEVICE DATABASES.

STATE: PRESERVED.  THE NEW NAMESPACE FRONT END CONTINUES TO READ THE EXISTING
AUTHORITATIVE PROCESS, DOMAIN, AND DEVICE OBJECTS; IT ADDS NO SHADOW DATABASE.

## 25. VIRTUAL FILESYSTEMS MUST BE CHEAP TO MOUNT

MONITORFS AND /DEV MUST NOT BUILD LARGE PERMANENT VNODE TREES.  LOOKUP,
READDIR, STAT, AND CONTENT SHOULD BE GENERATED ON DEMAND WHERE PRACTICAL.

STATE: PRESERVED SO FAR.  THE NEW ROOTS ARE SYNTHETIC ON-DEMAND VIEWS AND DO
NOT ALLOCATE A PERMANENT VNODE TREE.  CONTINUE TO CHECK THE HARD RESIDENT LIMIT
WHILE THE INTERNAL BACKENDS ARE CONSOLIDATED.

## 26. THIN NATIVE SYSCALLS

SYSCALL ENTRY CODE SHOULD VALIDATE/MARSHAL AND DISPATCH TO SUBSYSTEM LOGIC,
WITHOUT DUPLICATING THAT LOGIC IN THE DISPATCHER.

STATE: MOSTLY IMPLEMENTED.  THE EXTERNAL LEGACY DEVICE PATH IS GONE, BUT A
SMALL NUMBER OF INTERNAL DIRECT-DEVICE vnode constants remain in syscall/process
helpers.  REMOVE OR CENTRALIZE THOSE WHILE FINISHING THE MONITORFS BACKEND; NEW
SYSCALLS ADDED DURING USERSPACE DEVELOPMENT SHOULD REMAIN THIN.

## 27. AVOID UNNECESSARY PERMANENT OBJECT TABLES

DYNAMIC ALLOCATION IS PREFERRED FOR TRANSIENT OBJECTS WHEN IT SAVES TOTAL RAM;
SMALL FIXED TABLES REMAIN VALID WHEN THEY ARE CHEAPER.

STATE: IMPLEMENTED; PRESERVE IT.

## 28. BLOCKING IS EVENT DRIVEN

WAITING PROCESSES SLEEP AND ARE WOKEN BY THE RESPONSIBLE SUBSYSTEM.  BUSY
POLLING IS RESERVED FOR EARLY BOOT OR OTHER CASES WHERE NORMAL SLEEPING IS NOT
AVAILABLE OR WOULD BE MORE EXPENSIVE.

STATE: STRONGLY IMPLEMENTED.

## 29. COMPACT PDP-10-NATIVE REPRESENTATIONS

KERNEL STRUCTURES MAY USE 36-BIT WORDS, HALFWORDS, SIXBIT, AND OTHER NATIVE
PACKING WHEN THIS REDUCES TOTAL RAM/CODE COST.  PORTABILITY IS PROVIDED AT
CHOSEN INTERFACES, NOT BY INFLATING EVERY INTERNAL STRUCTURE.

STATE: STRONGLY IMPLEMENTED; PRESERVE IT.

## 30. ASSEMBLY FOR MEASURED FAST PATHS

PDP-6/PDP-10 ASSEMBLY IS APPROPRIATE WHERE IT MATERIALLY REDUCES RAM OR
EXECUTION TIME, INCLUDING SYSCALL, SCHEDULER, VM, COPY, AND LOW-LEVEL I/O PATHS.
C REMAINS PREFERRED WHERE ASSEMBLY HAS NO MEASURED PAYOFF.

STATE: STRONGLY IMPLEMENTED.  KCC-GENERATED CODE MAY BE REPLACED WITH ASSEMBLY
ONLY WHEN MEASUREMENT JUSTIFIES IT; COMPILER BUGS MUST BE FIXED IN KCC.

## 31. MINIMAL KERNEL BOOT PATH

KINIT DOES ONLY THE WORK REQUIRED TO ESTABLISH MEMORY, CORE PROCESS SERVICES,
ESSENTIAL DEVICES/STORAGE/VFS, THE ROOT ENVIRONMENT, AND THE FIRST USERSPACE
PROCESS.  BOOT-ONLY CODE/DATA IS RECLAIMED WHERE PRACTICAL.

STATE: MOSTLY IMPLEMENTED.  OPTIONAL RAMFS SETUP IS A CANDIDATE FOR USERSPACE
POLICY LATER.  THE EXTERNAL CTY PATH IS NOW /DEV/CTY0, BUT KINIT STILL BUILDS
THE INTERNAL DEVICE VNODE DIRECTLY; REMOVE THAT BACKEND DEPENDENCY DURING THE
REMAINING MONITORFS CONSOLIDATION.

## 32. USERSPACE OWNS SYSTEM INITIALIZATION

/SYSTEM/INIT IS PID 1 AND OWNS NORMAL SYSTEM POLICY: CONFIGURED CHILDREN,
ADDITIONAL MOUNTS, AND EVENTUALLY ACTIVATION OF CONFIGURED SWAP/LOGSTORE.

STATE: REAL INIT IS ALREADY THE PID-1 BOOT TARGET AND READS /CONFIG/INITTAB.
MOUNT/SWAP/LOGSTORE POLICY IS STILL TO BE MOVED/ADDED AS THE RELEVANT KERNEL
INTERFACES EXIST.  INIT MUST FIRST BE CONVERTED TO KCC UNDER POINT 15.

## 33. HARDWARE DISCOVERY IS SEPARATE FROM SERVICE POLICY

DRIVERS/STORAGE LAYERS DISCOVER AND EXPOSE HARDWARE.  ADMINISTRATIVE CHOICES
SUCH AS WHICH FILESYSTEM PROVIDES SWAP/LOGSTORE OR WHICH FILESYSTEMS/SERVICES
ARE ACTIVATED ARE SYSTEM CONFIGURATION, NOT DRIVER POLICY.

STATE: PARTIAL.  THE OLD DISKSET-OWNED SWAP/LOGSTORE MODEL VIOLATES THIS AND IS
REPLACED BY POINT 4.

## 34A. CURRENT IMPLEMENTATION ORDER

THE CURRENT ORDER IS FROZEN AS FOLLOWS UNLESS A NEW CORRECTNESS DEFECT OR A
COMPILER/ASSEMBLER BUG INTERRUPTS IT:

1. FINISH MONITORFS INTERNAL CONSOLIDATION.  THE /MONITOR + /DEV EXTERNAL
   NAMESPACE IS LIVE AND LEGACY ROOT NAMES ARE REMOVED; NOW FOLD THE TRANSITIONAL
   DEVFS/PROCFS/DOMAINFS BACKENDS TOGETHER AND REMOVE KINIT/HELPER DEPENDENCE ON
   DEVICEFS-SPECIFIC VNODE DETAILS.
2. CLOSE THE SMALL USERSPACE-DRIVEN FILESYSTEM/SYSCALL GAPS BEFORE THE LARGE
   PORT: SEEK, CHOWN, CORRECT DIRECTORY REMOVAL, AND D6FS MTIME/STAT/TOUCH
   UPDATE SUPPORT.  DO NOT ADD A BROAD SYSCTL/DEVIO COMPATIBILITY ABI.
3. IMPLEMENT SUBSTANTIAL DSH AGAINST THE STABILIZED NAMESPACE AND CURRENT
   RUN/WAIT/PIPE/DUP2/JOB-CONTROL ABI.  REUSE DAIMOSV1 PARSER, ENVIRONMENT, PATH,
   GLOB, AND COMMAND-UTILITY IDEAS; DO NOT COPY ITS SEQUENTIAL PIPELINE OR OLD
   PROCESS-CONTROL MODEL.
4. PORT THE USEFUL DAIMOSV1 CORE UTILITIES IN DEPENDENCY ORDER, REWRITING
   INTROSPECTION TO MONITORFS RATHER THAN RECREATING OLD SYSCTL/DEVIO INTERFACES.
5. CONTINUE WITH MAKE, DAS/DLINK/DARC, AND NATIVE KCC SELF-HOSTING.

## 34. RECOVERY/SINGLE-USER MODE IS POST-0.9

A MINIMAL RECOVERY ENVIRONMENT IS REQUIRED EVENTUALLY FOR FILESYSTEM REPAIR,
CONFIGURATION REPAIR, STORAGE MAINTENANCE, AND ADMINISTRATIVE SHELL ACCESS, BUT
ITS IMPLEMENTATION IS EXPLICITLY DEFERRED BEYOND DAIMOS 0.9.  EXISTING DESIGN
NOTES MAY REMAIN, MARKED DEFERRED.

STATE: INTENTIONALLY NOT IMPLEMENTED FOR 0.9.

## 35. BOOT-TIME CONFIGURATION IS EXPLICIT

PERSISTENT ADMINISTRATOR POLICY LIVES IN ORDINARY CONFIGURATION UNDER /CONFIG
WHERE PRACTICAL.  RUNTIME/OBSERVATION STATE BELONGS UNDER /MONITOR, NOT /CONFIG.

STATE: PARTIAL.  /CONFIG/INITTAB AND /CONFIG/PASSWD EXIST.  ADD MOUNT AND
SWAP/LOGSTORE ACTIVATION CONFIGURATION WHEN THOSE USERSPACE INTERFACES EXIST.

## 36. NATIVE CREDENTIALS

UID/GID CREDENTIALS ARE KERNEL PROCESS STATE AND ARE USED BY COMMON VFS/
AUTHORIZATION CODE.

STATE: IMPLEMENTED AS A COMPACT 18-BIT UID + 18-BIT GID WORD WITH GET/SET
OPERATIONS AND INHERITANCE.

## 37. D6FS UNIX-LIKE OWNER/GROUP/MODE PERMISSIONS

D6FS PERSISTS UID/GID/MODE WHILE GENERIC FILE CODE APPLIES OWNER/GROUP/OTHER
ACCESS POLICY SO OTHER FILESYSTEMS CAN PARTICIPATE WITHOUT DUPLICATING POLICY.

STATE: SUBSTANTIALLY IMPLEMENTED.  THE FILE_RENAME DESTINATION-DIRECTORY
PERMISSION BUG FOUND DURING THE 2026-09-18 AUDIT IS FIXED: ACCESS IS CHECKED
ONLY AFTER THE DESTINATION PARENT HAS BEEN RESOLVED.  PERMANENT REGRESSION
COVERAGE STILL BELONGS IN THE TESTKIT.

## 38. SIMPLE UID-0 PRIVILEGE MODEL

UID 0 IS THE ADMINISTRATIVE IDENTITY FOR 0.9.  DO NOT ADD CAPABILITIES OR
PRIVILEGE SETS WITHOUT A CONCRETE REQUIREMENT.  COMMON CHECKS ARE PREFERRED TO
SCATTERED UID-0 SPECIAL CASES.

STATE: IMPLEMENTED CLEANLY.

## 39. DOMAINS DO NOT REPLACE CREDENTIALS

UID/GID/MODE ANSWER RESOURCE AUTHORIZATION; DOMAINS ANSWER PROCESS-CONTROL
SCOPE; SESSIONS AND PROCESS GROUPS ANSWER TERMINAL/JOB-CONTROL RELATIONSHIPS.
THESE REMAIN ORTHOGONAL.

STATE: IMPLEMENTED.

## 40. MONITORFS AND /DEV USE NORMAL AUTHORIZATION

VIRTUAL KERNEL STATE IS NOT AN AUTHORIZATION BYPASS.  /MONITOR OBSERVATION OR
CONTROL OBJECTS AND /DEV I/O ENDPOINTS RECEIVE EXPLICIT MODES/OWNERSHIP AND
