## 1. HARDWARE BASELINE

DAIMOS TARGETS A PDP-6 WITH 32K WORDS OF CORE AS THE INITIAL/MINIMUM MACHINE.
PDP-10 SUPPORT MUST NOT SILENTLY RAISE THAT BASELINE.

STATE: IMPLEMENTED IN THE CORE DESIGN AND LOW-MEMORY TESTS.  A COMPLETE 32K
INIT -> LOGIN -> DSH ACCEPTANCE RUN MUST REMAIN A RELEASE GATE.

## 2. KERNEL MEMORY BUDGET

THE HARD ARCHITECTURAL KERNEL BUDGET IS BELOW 16K WORDS INCLUDING ALL RESIDENT
AND SCRATCH KERNEL MEMORY.  THE CURRENT SHRINK TARGET IS A 14K TOTAL KERNEL
FOOTPRINT.  BECAUSE LOW CORE FROM 000000 THROUGH ABOUT 000060 IS NOT PART OF
THE KCORE+MRES LINK TOTAL, THE EQUIVALENT CURRENT ACCEPTANCE LIMIT IS:

    KCORE + MRES <= 14288 DECIMAL WORDS

THE CURRENT KCC SHRINK CANDIDATE MEASURES 14275 WORDS OF KCORE+MRES.  ITS
PERMANENT HIGH-WATER ADDRESS IS 033762 OCTAL (14302 DECIMAL), 13 WORDS BELOW
THE HARD PERMANENT CEILING OF 033777 OCTAL (14335 DECIMAL).  THE KCC BUILD IS
THE ACCEPTANCE BUILD.  GCC MAY BE MEASURED FOR CODE-QUALITY COMPARISON BUT DOES
NOT RELAX THE KCC LIMIT.

STATE: SIZE TARGET MET WITH 13 WORDS OF HEADROOM; FULL FRESH LOGIN ACCEPTANCE
STILL REQUIRED BEFORE THE SHRINK PASS IS CLOSED.  ALL ACTIVE 11500-, 11999-,
12-KIWORD, 12288-, 13-KIWORD, AND 13312-WORD RULES ARE OBSOLETE AND MUST NOT BE
USED AS ACCEPTANCE LIMITS.

## 3. CURRENT DEVELOPMENT PHASE

DAIMOS HAS REACHED MULTIUSER USERSPACE.  THE CURRENT KERNEL SHRINK/CLEANUP PASS
MUST FIRST REACH THE 14288-WORD KCORE+MRES TARGET.  AFTER RECONCILIATION AND
THIS SHRINK PASS, DEVELOPMENT MOVES PRIMARILY TO USERSPACE.

STATE: ACTIVE.  REAL INIT/LOGIN/DSH ALREADY BOOTS; THE IMMEDIATE USERSPACE
BLOCKER IS THE KCC CONVERSION IN POINT 15.

## 4. D6FS SWAP AND LOGSTORE RESERVATIONS

EACH D6FS FILESYSTEM MAY CONTAIN ZERO OR ONE SWAP RESERVATION AND ZERO OR ONE
LOGSTORE RESERVATION.  THEY ARE NOT FILES AND HAVE NO ORDINARY FILE I/O OR
NAMESPACE SEMANTICS.  D6FS OWNS THEIR PERSISTENT LOGICAL RESERVATIONS AND
EXCLUDES THE BLOCKS FROM NORMAL ALLOCATION.

VFS DISCOVERS AND REGISTERS THE RESOLVED BACKING LOGICAL RANGE.  ONCE ACTIVE,
SWAP/LOGSTORE I/O BYPASSES FILE I/O AND USES THE LOWER BLOCK/DISKSET FAST PATH.
THE DISKSET LAYER ALONE CHOOSES PHYSICAL DISTRIBUTION, SCHEDULING, AND BAD-MEDIA
MAPPING.  LOGICAL RESERVATIONS ARE CONTIGUOUS EVEN WHEN THEIR PHYSICAL STORAGE
IS DISTRIBUTED OR SKIPS BAD MEDIA.

ON SPINNING DISKS, SWAP IS PREFERRED AT THE FAST OUTER EDGE AND LOGSTORE AT THE
INNER EDGE DIRECTLY AFTER THE BOOT AREA.  SIZES AND BOUNDARIES ARE ALIGNED TO
DEVICE-PERFORMANCE GEOMETRY, NOT TO A RAM-SIZE MULTIPLIER.  DRUMSETS HAVE NO
INNER/OUTER RULE.  RESERVATIONS MAY BE CREATED, GROWN, SHRUNK, MOVED, OR
DELETED OFFLINE; MOVEMENT PRESERVES CONTENTS.  PACKFS PROVIDES FREE-RUN
PREPARATION.  MKFS.D6FS ACCEPTS INITIAL SWAP/LOGSTORE SIZES.  FSCK VALIDATES
AND REPAIRS THE RESERVATION/ALLOCATION RELATIONSHIP.  A FILESYSTEM PROVIDING
ACTIVE SWAP OR LOGSTORE CANNOT BE UNMOUNTED.

STATE: DESIGN ACCEPTED, MIGRATION NOT YET IMPLEMENTED.  CURRENT DISKSET
SWAP/LOGSTORE LAYOUT FIELDS AND SEMANTIC ENTRY POINTS MUST MOVE UP INTO
D6FS/VFS; THE RUNTIME BAD-MEDIA PATH MUST ALSO BECOME COMMON BELOW D6FS,
SWAP, AND LOGSTORE.  MULTI-MOUNT D6FS STATE MUST NOT ASSUME A SINGLE GLOBAL
FILESYSTEM.

## 5. DEVELOPMENT PRIORITY

CORRECTNESS REGRESSIONS, ESPECIALLY COMPILER OR ASSEMBLER BUGS, TAKE PRIORITY
OVER NEW FEATURES.  FIX DEFECTS AT THEIR SOURCE; DO NOT ADD WORKAROUNDS.
FEATURE CREEP IS AVOIDED.

STATE: ACTIVE DEVELOPMENT RULE.

## 6. MACHINE-INDEPENDENT KERNEL BOUNDARIES

MACHINE-INDEPENDENT KERNEL POLICY IS SEPARATED FROM PDP-6/PDP-10 MECHANISMS
WHERE THIS DOES NOT COST MEANINGFUL RAM OR TIME.  MACHINE-SPECIFIC FAST PATHS
REMAIN PERMITTED AND IMPORTANT.

STATE: MOSTLY IMPLEMENTED.  THE STORAGE-SET LAYER STILL CONTAINS DSK270-SPECIFIC
ASSUMPTIONS THAT SHOULD MOVE BEHIND THE GENERIC LOGICAL BLOCK/SET BOUNDARY WHEN
THAT AREA IS NEXT REWORKED.

## 7. REPLACEABLE VM/MM BACKEND

GENERIC PROCESS, EXEC, SCHEDULER, VFS, AND OTHER KERNEL CODE MUST NOT DEPEND ON
THE PDP-6 CONTIGUOUS-PHYSICAL-IMAGE REPRESENTATION.  THE PDP-6 VM BACKEND USES
RELOCATION/PROTECTION, COMPACTION, AND WHOLE-IMAGE SWAPPING.  A LATER HARDWARE
PAGER BACKEND MAY REPLACE IT WITHOUT CHANGING THE PROCESS ABI.

STATE: IMPLEMENTED.  THE PDP-6 SWAP BACKEND ONLY NEEDS TO CONSUME THE GENERIC
VFS-REGISTERED SWAP RANGE WHEN POINT 4 IS MIGRATED.

## 8. ASYNCHRONOUS BLOCK I/O

DISK AND DRUM I/O IS ASYNCHRONOUS FROM THE PROCESS PERSPECTIVE.  PROCESSES WAIT
ON EVENTS WHILE THE CPU REMAINS AVAILABLE.  EARLY-BOOT AND SLOT-0 SWAP POLLING
ARE VALID SPECIAL CASES WHERE NORMAL SLEEPING IS NOT AVAILABLE.

STATE: SUBSTANTIALLY IMPLEMENTED.

## 9. DCT AND CONTROLLER SCHEDULING

MULTIPLE DISKS MAY HAVE OUTSTANDING MECHANICAL ACTIVITY, BUT THE SHARED
CONTROLLER/DCT PATH DOES NOT PROVIDE INDEPENDENT SIMULTANEOUS MEMORY-TRANSFER
STREAMS.  SCHEDULING SHOULD EXPLOIT SEEK/ROTATIONAL OVERLAP BETWEEN SPINDLES
AND THEN SCHEDULE THE SHARED TRANSFER RESOURCE.  DRUMS USE THEIR OWN
GEOMETRY/TIMING POLICY.

STATE: PARTIAL.  SHARED DCT OWNERSHIP AND PER-UNIT QUEUES EXIST, BUT CROSS-
SPINDLE MECHANICAL OVERLAP SELECTION AND DRUM ROTATIONAL SCHEDULING STILL NEED
A DEDICATED SCHEDULER PASS.  DO THIS AFTER THE STORAGE OWNERSHIP CLEANUP.

## 10. COMPATIBILITY PERSONALITIES

THE NATIVE DAIMOS ABI AND IMPLEMENTATION ARE AUTHORITATIVE.  ITS/TENEX
PERSONALITIES MAY BE ENABLED FOR TESTING BUT MUST NOT DICTATE NATIVE DESIGN OR
COST NORMAL RESIDENT MEMORY WHEN DISABLED.

STATE: IMPLEMENTED; PRESERVE IT.

## 11. NATIVE INTERFACES FIRST

KERNEL SYSCALLS AND INTERNAL APIS ARE NATIVE DAIMOS FACILITIES.  COMPATIBILITY
LAYERS TRANSLATE ONTO THEM RATHER THAN DEFINING THE NATIVE ABI.

STATE: IMPLEMENTED; PRESERVE IT.

## 12. PROCESS, SESSION, AND JOB CONTROL

PROCESS GROUPS, SESSIONS, CONTROLLING TERMINALS, FOREGROUND/BACKGROUND GROUPS,
STOP/CONTINUE, AND REQUIRED EVENTS ARE NATIVE KERNEL STATE.  DSH MUST USE THEM
FOR PIPELINES, BACKGROUND JOBS, CTRL-Z, BG, FG, WAITING, AND TERMINAL HANDOFF.
NO SESSIONFS IS REQUIRED.

STATE: KERNEL SUPPORT IS LARGELY IMPLEMENTED AND TESTED.  DSH STILL NEEDS
PIPELINES, BACKGROUND JOBS, JOB TABLES, FG/BG, AND FOREGROUND TERMINAL HANDOFF.

## 13. PIPES AND FIFOS

PIPES ARE NATIVE KERNEL IPC OBJECTS.  THE CURRENT IMPLEMENTATION USES A
128-CHARACTER BUFFER, PIPE_BUF=128 ATOMIC WRITES, BLOCKING READERS/WRITERS,
EOF/BROKEN-PIPE HANDLING, DESCRIPTOR INHERITANCE, AND FILESYSTEM-NAMED FIFOS
WITH TRANSIENT STREAM CONTENTS.

STATE: KERNEL IMPLEMENTATION IS ESSENTIALLY COMPLETE.  DSH MUST NOW USE THE
EXISTING PIPE FACILITY FOR PIPELINES; DO NOT REPLACE IT SPECULATIVELY.

## 14. SELF-HOSTING OBJECTIVE

THE PRINCIPAL USERSPACE OBJECTIVE IS A COHERENT SELF-HOSTING ENVIRONMENT:
DSH, MAKE, DAS, KCC, AND THEIR REQUIRED LIBRARIES/UTILITIES.  OPTIONAL FEATURES
MUST NOT DISPLACE THIS PATH.

STATE: EARLY STAGE.  INIT, LOGIN, DSH, LIBC, AND BASIC COMMAND SUPPORT EXIST.

## 15. KCC IS THE MANDATORY DAIMOS C COMPILER

KCC IS THE NORMAL DAIMOS C COMPILER FOR BOTH KERNEL AND USERSPACE.  GCC MAY
REMAIN AS A COMPARISON/REFERENCE COMPILER, BUT IT IS NOT THE NORMAL DAIMOS
BUILD COMPILER.  ANY KCC OR DAS DEFECT EXPOSED BY CONVERSION HAS PRIORITY AND
MUST BE FIXED PROPERLY.

STATE: IMMEDIATE BLOCKER.  THE KERNEL IS BUILT WITH KCC, BUT CURRENT USERSPACE
STILL USES GCC/LIBGCC.  BEFORE ANY FURTHER USERSPACE FEATURE DEVELOPMENT,
CONVERT LIBC, INIT, LOGIN, DSH, AND EXISTING USERSPACE TARGETS TO KCC; REMOVE
NORMAL LIBGCC DEPENDENCE; THEN PROVE INIT -> LOGIN -> DSH WITH KCC-BUILT
USERSPACE.  RUNNING KCC ITSELF UNDER DAIMOS IS A LATER SELF-HOSTING MILESTONE.

## 16. NATIVE PROCESS EVENTS

DAIMOS USES A SMALL NATIVE EVENT MECHANISM FOR INTERRUPT, TERMINATION, HANGUP,
STOP/CONTINUE, ALARM, CHILD, BROKEN-PIPE, AND RELATED PROCESS CONTROL.

STATE: SUBSTANTIALLY IMPLEMENTED.  DO NOT ADD A FULL POSIX SIGNAL MODEL UNLESS
REAL USERSPACE REQUIRES SPECIFIC CATCH/IGNORE/MASK SEMANTICS.

## 17. DOMAINS

DOMAINS ARE NATIVE PROCESS-CONTROL/ISOLATION SCOPES DISTINCT FROM SESSIONS,
PROCESS GROUPS, AND CREDENTIALS.  MEMBERSHIP IS INHERITED AND THE KERNEL
PROVIDES EXPLICIT DOMAIN CONTROL/QUERY OPERATIONS.

STATE: IMPLEMENTED.  THE CURRENT DOMAINFS PRESENTATION WILL MOVE INTO
MONITORFS; THE DOMAIN PRIMITIVE REMAINS.

## 18. DESCRIPTOR-BASED USERSPACE I/O

FILES, TERMINALS, PIPES/FIFOS, DEVICES, AND OTHER I/O OBJECTS USE COMMON FILE
DESCRIPTORS SO INHERITANCE, DUPLICATION, REDIRECTION, AND CLOSE SEMANTICS ARE
UNIFORM.

STATE: SUBSTANTIALLY IMPLEMENTED.  ADD SMALL DESCRIPTOR SYSCALLS ONLY WHEN
USERSPACE WORK DEMONSTRATES A NEED.

## 19. MONITORFS AND THE /DEV VIEW

MONITORFS WILL BE THE SINGLE KERNEL-STATE VIRTUAL FILESYSTEM, MOUNTED AT
/MONITOR.  PROCESS, DOMAIN, SESSION, DEVICE STATE, KERNEL STATE, AND SIMILAR
INTROSPECTION/CONTROL LIVE THERE.  THERE IS NO /PROC FILESYSTEM.

/DEV IS AN ALTERNATE VIEW IMPLEMENTED BY THE SAME MONITORFS CODE AND EXPOSES
ONLY DEVICE I/O ENDPOINTS.  DEVICE STATUS/CONFIGURATION/STATISTICS BELONG UNDER
/MONITOR/DEVICES.  THE CURRENT DEVFS, PROCFS, AND DOMAINFS IMPLEMENTATIONS ARE
TO BE CONSOLIDATED, NOT RETAINED AS COMPATIBILITY FILESYSTEMS.

STATE: NOT YET IMPLEMENTED.  THIS IS A LATER KERNEL PHASE AND DOES NOT BLOCK
THE IMMEDIATE USERSPACE/KCC WORK.

## 20. DEMAND-ALLOCATED KERNEL FACILITIES

EXPENSIVE PER-OBJECT STATE SHOULD CONSUME MEMORY ONLY WHILE THE OBJECT EXISTS
WHERE PRACTICAL.  FIXED TABLES ARE USED ONLY WHEN THEY ARE SMALLER/FASTER.

STATE: STRONGLY IMPLEMENTED IN PROCESS, U-AREA, PIPE, VM, AND MM ALLOCATION.
PRESERVE THIS DURING MONITORFS/VFS WORK.

## 21. VFS OWNS NAMESPACE SEMANTICS

PATH WALKING, MOUNT CROSSING, DESCRIPTOR INTEGRATION, AND GENERIC FILESYSTEM
DISPATCH ARE VFS/GENERIC FILE-LAYER RESPONSIBILITIES.  FILESYSTEM PROVIDERS
IMPLEMENT THEIR OBJECTS WITHOUT DUPLICATING PATH SEMANTICS.

STATE: MOSTLY IMPLEMENTED.  CURRENT /DEVICE, /PROC, AND /DOMAIN SPECIAL CASES
IN GENERIC VFS/FILE CODE MUST DISAPPEAR DURING MONITORFS CONSOLIDATION.

## 22. SPECIALIZED STATE FILESYSTEMS ARE REPLACED BY MONITORFS

PROCFS, DOMAINFS, AND THE MONITORING/ADMINISTRATIVE PART OF DEVFS ARE MIGRATED
INTO /MONITOR AND THE REDUNDANT FILESYSTEM IMPLEMENTATIONS ARE REMOVED.

STATE: NOT YET IMPLEMENTED; LATER KERNEL WORK.

## 23. /DEV IS I/O ONLY AND PART OF MONITORFS

/DEV IS NOT A SEPARATE DEVFS.  IT IS A SMALL ALTERNATE MONITORFS VIEW THAT
EXPOSES ONLY OPENABLE DEVICE I/O ENDPOINTS.  THE SAME UNDERLYING DEVICE OBJECTS
ARE OBSERVED/CONTROLLED THROUGH /MONITOR/DEVICES.

STATE: NOT YET IMPLEMENTED; LATER KERNEL WORK.

## 24. MONITORFS VIEWS LIVE KERNEL STATE

MONITORFS MUST GENERATE VIEWS FROM AUTHORITATIVE KERNEL OBJECTS RATHER THAN

STATE: THE CURRENT PROCFS/DOMAINFS/DEVFS ALREADY FOLLOW THIS PRINCIPLE.
PRESERVE IT DURING CONSOLIDATION.

## 25. VIRTUAL FILESYSTEMS MUST BE CHEAP TO MOUNT

MONITORFS AND /DEV MUST NOT BUILD LARGE PERMANENT VNODE TREES.  LOOKUP,

STATE: CURRENT SYNTHETIC FILESYSTEMS ARE ALREADY CHEAP.  THE CONSOLIDATION
SHOULD REDUCE OR AT LEAST NOT INCREASE RESIDENT CODE/DATA.

## 26. THIN NATIVE SYSCALLS

SYSCALL ENTRY CODE SHOULD VALIDATE/MARSHAL AND DISPATCH TO SUBSYSTEM LOGIC,
WITHOUT DUPLICATING THAT LOGIC IN THE DISPATCHER.

STATE: MOSTLY IMPLEMENTED.  DEVICEFS-SPECIFIC VNODE KNOWLEDGE IN SYSCALL CODE
MUST BE REMOVED DURING MONITORFS WORK.  NEW SYSCALLS ADDED DURING USERSPACE
DEVELOPMENT SHOULD REMAIN THIN.

## 27. AVOID UNNECESSARY PERMANENT OBJECT TABLES

DYNAMIC ALLOCATION IS PREFERRED FOR TRANSIENT OBJECTS WHEN IT SAVES TOTAL RAM;
SMALL FIXED TABLES REMAIN VALID WHEN THEY ARE CHEAPER.

STATE: IMPLEMENTED; PRESERVE IT.

## 28. BLOCKING IS EVENT DRIVEN

WAITING PROCESSES SLEEP AND ARE WOKEN BY THE RESPONSIBLE SUBSYSTEM.  BUSY
POLLING IS RESERVED FOR EARLY BOOT OR OTHER CASES WHERE NORMAL SLEEPING IS NOT
AVAILABLE OR WOULD BE MORE EXPENSIVE.

STATE: STRONGLY IMPLEMENTED.

## 29. COMPACT PDP-10-NATIVE REPRESENTATIONS

KERNEL STRUCTURES MAY USE 36-BIT WORDS, HALFWORDS, SIXBIT, AND OTHER NATIVE
PACKING WHEN THIS REDUCES TOTAL RAM/CODE COST.  PORTABILITY IS PROVIDED AT
CHOSEN INTERFACES, NOT BY INFLATING EVERY INTERNAL STRUCTURE.

STATE: STRONGLY IMPLEMENTED; PRESERVE IT.

## 30. ASSEMBLY FOR MEASURED FAST PATHS

PDP-6/PDP-10 ASSEMBLY IS APPROPRIATE WHERE IT MATERIALLY REDUCES RAM OR
EXECUTION TIME, INCLUDING SYSCALL, SCHEDULER, VM, COPY, AND LOW-LEVEL I/O PATHS.
C REMAINS PREFERRED WHERE ASSEMBLY HAS NO MEASURED PAYOFF.

STATE: STRONGLY IMPLEMENTED.  KCC-GENERATED CODE MAY BE REPLACED WITH ASSEMBLY
ONLY WHEN MEASUREMENT JUSTIFIES IT; COMPILER BUGS MUST BE FIXED IN KCC.

## 31. MINIMAL KERNEL BOOT PATH

KINIT DOES ONLY THE WORK REQUIRED TO ESTABLISH MEMORY, CORE PROCESS SERVICES,
ESSENTIAL DEVICES/STORAGE/VFS, THE ROOT ENVIRONMENT, AND THE FIRST USERSPACE
PROCESS.  BOOT-ONLY CODE/DATA IS RECLAIMED WHERE PRACTICAL.

STATE: MOSTLY IMPLEMENTED.  OPTIONAL RAMFS SETUP IS A CANDIDATE FOR USERSPACE
POLICY LATER.  KINIT'S CURRENT DIRECT DEVICEFS CTY0 DEPENDENCY MUST FOLLOW THE
MONITORFS /DEV ABSTRACTION WHEN THAT WORK IS DONE.
