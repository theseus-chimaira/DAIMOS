## 2. DATA-LAYOUT AUDITS FOR PDP-6 INSTRUCTION COST

REVIEW compact resident structures for layouts which reduce both storage and

### 2.1 KCORE ACCUMULATOR / REGISTER-LIVENESS AUDIT (2026-10-27)

ACTIVE CANDIDATE; SOURCE-LEVEL CENSUS ONLY, NO CLAIMED RAM SAVING.

THE PDP-6 HAS SIXTEEN ACCUMULATORS (OCTAL AC0..AC17). ALL ARE USED IN
KCORE: AC17 IS THE PUSHDOWN POINTER; AC0..AC7 ARE GENERALLY CALLER-SCRATCH,
AND AC10..AC16 ARE CALLEE-SAVED BY THE KERNEL C ABI. NO REGISTER IS
GLOBALLY FREE. AC10..AC16 MUST NOT BE REUSED ACROSS CALLS WITHOUT THEIR
REQUIRED PRESERVATION, AND INTERRUPT/CONTEXT-SWITCH STATE MUST REMAIN SOUND.

A 2026-10-27 CENSUS OF THE 78 SYSTEM/KERNEL ASSEMBLY FILES COUNTED
INSTRUCTIONS WITH AN EXPLICIT ACCUMULATOR AS FIRST OPERAND (NOT TOTAL
READS, LIVE RANGES, OR LINKED INSTRUCTION COUNTS). SELECTED COUNTS:

    AC1  3510       AC2  1633       AC3  1185       AC4  1236
    AC5   846       AC6   731       AC7   480       AC0   600
    AC10  276       AC11  322       AC12  277       AC13  238
    AC14  203       AC15  184       AC16  146       AC17 2790

CALLEE-SAVED FIRST-OPERAND SHARE: VFS 0.0%, SYSCALL DISPATCH 0.5%,
MONITORFS RUNTIME 4.2%, FILE RUNTIME 5.5%, MEMFS RUNTIME 8.8%,
D6FS RUNTIME 9.4%, DTFS RUNTIME 10.1%, TSFS RUNTIME 10.5%.
THESE FIGURES INDICATE UNEVEN USAGE, NOT PROVEN FREE REGISTERS OR SAVINGS.
HIGHER AC USE ALONE IS NOT AN OPTIMIZATION: ENTRY/EXIT SAVE COST MAY
OUTWEIGH AVOIDED RELOADS, ESPECIALLY FOR SHORT LEAF ROUTINES.

NEXT: TRACE COMPLETE FILE -> VFS -> PROVIDER AND SYSCALL CALL CHAINS.
FOR EACH ROUTINE RECORD REGISTER LIVE-IN/LIVE-OUT, CLOBBERS, VALUES LIVE
ACROSS CALLS, STACK SLOTS, SAVE/RESTORE TRAFFIC AND REPEATED RELOADS.
COMPARE CURRENT ABI AGAINST A COMPACT INTERNAL REGISTER CONTRACT THAT
REUSES ALREADY-LIVE VALUES OR REMOVES DUPLICATE MARSHALLING. ALSO REVIEW
EXEC/VM/SWAP AS POSITIVE EXAMPLES OF LONG-LIVED CALLEE-SAVED STATE.

ACCEPT ONLY MEASURED SHRINKAGE OF THE SAME FULLY LINKED/FOLDED KCORE
AND PERMANENT IMAGE PROFILE, INCLUDING INSTALLED MRES AND PERSISTENT DATA.
REGISTER RESIDENCY BY ITSELF DOES NOT SHRINK PERMANENT RAM; REMOVING
INSTRUCTIONS, STATIC SPILL AREAS OR PERMANENT DATA CAN. REDUCED DYNAMIC
STACK DEPTH IS A SEPARATE BENEFIT AND MUST BE MEASURED, NOT DOUBLE-COUNTED
AS PERMANENT RAM SAVING. EXECUTION SPEED IS SECONDARY. PRESERVE THE
DOCUMENTED ABI, PROVIDER REMOVABILITY, FILESYSTEM SEMANTICS AND INTERRUPT
SAFETY; TEST IN DAIMOS-TESTKIT. REVERT EXPERIMENTS WITH NET RAM GROWTH.

### 3.1 CROSS-DOMAIN P10FOLD

RUN THE FINAL CROSS-DOMAIN CENSUS ONLY AFTER SOURCE-LEVEL SHRINKING STABILIZES.
THE CURRENT broad all-MRES-symbol experiment found about 46 words of possible
one-JRST folds, which is only an upper bound because hot paths were deliberately

PROCEED ONLY IF A CONSERVATIVE COLD-SYMBOL SET STILL SAVES MORE THAN ABOUT 20
PERMANENT WORDS AND KCORE DOES NOT GROW.

P10FOLD CURRENTLY ANALYZES THESE CROSS-DOMAIN EXTERNAL-ANCHOR FOLDS BUT DOES
NOT EMIT AN EXECUTABLE CROSS-DOMAIN FOLD PLAN.  IF THE CONSERVATIVE CENSUS
STILL QUALIFIES, COMPLETE THAT TOOLING IN TOOLS/HOST RATHER THAN hand-coding
ad-hoc DAIMOS trampolines.

### 3.2 PATCH-TO-FOLD / BOOT-CONSTANT SPECIALIZATION

FOR NEAR-DUPLICATE COLD ROUTINES WHICH DIFFER ONLY IN A FEW AC, EA, DEVICE,
OR TARGET FIELDS, CONSIDER INITIALIZATION-TIME PATCHING SO ONE common body can
serve multiple cases.

USE THIS ONLY WHEN:

- the differences are boot-constant or otherwise immutable while executing;
- no runtime branch/dispatch cost is added to a hot path;
- the final linked saving is material, preferably more than about 20 words;
- patch sites and invariants are documented as part of the internal ABI.

DO NOT introduce general runtime self-modification merely to make source look
more uniform.
