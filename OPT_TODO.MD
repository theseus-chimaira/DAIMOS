# DAIMOS OPTIMIZATION TODO

THIS FILE CONTAINS OPTIMIZATION INVESTIGATIONS AND POSSIBLE FOLLOW-UP WORK.

## PROCESS EXECUTIVE AREA

PERFORM A THOROUGH INSPECTION OF THE PER-PROCESS STABLE EXECUTIVE AREA BEFORE
ACCEPTING ITS PRESENT SIZE OR CHANGING ITS LAYOUT.

### 1. BUILD AN EXACT WORD MAP

- MAP EVERY WORD AND RANGE IN THE PER-PROCESS EXECUTIVE AREA.
- IDENTIFY SAVED CPU STATE, SYSCALL STATE, CWD STATE, FILE-DESCRIPTOR STATE,
  KERNEL STACK, PADDING, RESERVED RANGES, AND UNUSED HOLES.
- VERIFY ALL ASSEMBLY AND C CONSTANTS AGAINST THE SAME MAP.
- SEPARATE CONTEXT-SIZE CONSTANTS FROM BOOTSTRAP-STACK CONSTANTS.
- INVESTIGATE PROC_KCTX_WORDS AND PROVE WHAT THE VALUE 0060 ACTUALLY MEANS.
- REMOVE OR RENAME ANY CONSTANT WHOSE NAME DOES NOT MATCH ITS REAL PURPOSE.
- ADD BUILD-TIME OR TEST-TIME CHECKS THAT PREVENT C AND ASSEMBLY LAYOUTS FROM
  SILENTLY DIVERGING.

### 2. MEASURE REAL KERNEL STACK DEPTH

DO NOT REDUCE THE PRIVATE KERNEL STACK BY GUESSWORK.

- CENSUS EVERY ENTRY PATH THAT CAN RUN ON A PROCESS-PRIVATE KERNEL STACK.
- INCLUDE ALL SYSCALL PATHS.
- INCLUDE VFS AND FILESYSTEM PROVIDER PATHS.
- INCLUDE PIPE, TTY, WAIT, WAKEUP, EXIT, EXEC, FORK, AND SCHEDULER PATHS.
- INCLUDE ERROR AND CLEANUP PATHS, NOT ONLY SUCCESS PATHS.
- INCLUDE PATHS THAT CAN SLEEP AND LATER RESUME AN EXECUTIVE CONTINUATION.
- INCLUDE INTERRUPT OR PI INTERACTION THAT CAN CONSUME THE SAME STACK.
- ACCOUNT FOR PDP-6 PUSHJ/PUSH FRAME USE AND KCC GENERATED C STACK USE.
- FIND THE WORST STATIC CALL CHAIN.
- ADD STACK-WATERMARK INSTRUMENTATION IN DAIMOS-TESTKIT WHERE PRACTICAL.
- EXERCISE THE WORST PATHS AND RECORD THE HIGHEST OBSERVED STACK USE.
- COMPARE STATIC AND DYNAMIC RESULTS.
- DETERMINE A SMALL, EXPLICIT SAFETY MARGIN.
- SET THE STACK SIZE FROM EVIDENCE, NOT FROM A ROUND CONSERVATIVE RESERVATION.

### 3. INSPECT SLEEPING CONTINUATIONS

THE EXECUTIVE AREA MUST REMAIN SAFE WHEN A USER EXTENT MOVES OR IS SWAPPED.
OPTIMIZE THIS REQUIREMENT WITHOUT WEAKENING IT.

- IDENTIFY EXACTLY WHICH WORDS MUST REMAIN RESIDENT FOR A SLEEPING PROCESS.
- PROVE WHICH STACK FRAMES MAY BE LIVE ACROSS PROC_WAIT_EVENT.
- CHECK WHETHER ALL SLEEPABLE PATHS NEED THE SAME MAXIMUM STACK RESERVATION.
- INVESTIGATE WHETHER SLEEP-SAFE CONTINUATION STATE CAN BE MADE SHALLOWER OR
  MORE COMPACT WITHOUT ADDING EXTRA TRAPS, COPIES, OR COMMON-CASE OVERHEAD.
- DO NOT INTRODUCE A WORKAROUND THAT COPIES OR RECONSTRUCTS ARBITRARY C STACKS.
- PRESERVE STABLE PHYSICAL EXECUTIVE CONTINUATIONS UNTIL A BETTER DESIGN IS
  PROVEN CORRECT AND CHEAPER.

### 4. INSPECT FILE-DESCRIPTOR RESIDENT COST

- CENSUS EVERY WORD USED BY ONE FILE DESCRIPTOR.
- DETERMINE THE REQUIRED BIT WIDTH OF VNODE, OFFSET, FLAGS, TYPE, AND OTHER
  METADATA FIELDS.
- IDENTIFY VALUES THAT CAN BE DERIVED FROM VFS OR OPEN-FILE OBJECT STATE.
- LOOK FOR SAFE HALF-WORD OR BIT-FIELD PACKING.
- LOOK FOR STRUCTURAL SHARING BETWEEN DESCRIPTORS WHERE SEMANTICS ALLOW IT.
- CHECK WHETHER PER-PROCESS OFFSET STORAGE IS REQUIRED FOR EVERY DESCRIPTOR.
- DO NOT TRADE A LARGE EXECUTION-SPEED LOSS FOR A SMALL WORD SAVING.
- DO NOT CHANGE THE USER ABI MERELY TO SAVE INTERNAL WORDS.

### 5. INSPECT CWD AND OTHER PER-PROCESS STATE

- CHECK WHETHER CWD NEEDS A FULL WORD.
- CHECK WHETHER ANY PROCESS-PRIVATE STATE DUPLICATES VFS, MM, MODULE, OR
  SCHEDULER STATE.
- PACK OR DERIVE STATE WHEN THE RESULT IS CLEARER AND NO SLOW HOT-PATH LOOKUP
  IS INTRODUCED.
- FIND AND REMOVE UNUSED RESERVED WORDS.

### 6. REDUCE THE AREA ONLY AFTER THE CENSUS

- DEFINE THE MINIMUM PROVEN FIXED PREFIX.
- DEFINE THE MINIMUM PROVEN PRIVATE KERNEL STACK PLUS SAFETY MARGIN.
- RECALCULATE PROC_USTACK_BASE, PROC_KSTACK_WORDS, AND PROC_UAREA_WORDS.
- UPDATE EVERY C AND ASSEMBLY USER TOGETHER.
- KEEP THE PROCESS DESCRIPTOR AT THREE WORDS UNLESS A SEPARATE MEASURED CHANGE
  PROVES THAT GROWING IT SAVES MORE RESIDENT MEMORY ELSEWHERE.
- VERIFY THAT USER EXTENT COMPACTION AND SWAPPING STILL CANNOT INVALIDATE A
  SAVED EXECUTIVE CONTINUATION.

### 7. TEST REQUIREMENTS

ADD REGRESSIONS TO DAIMOS-TESTKIT FOR THE FINAL LAYOUT.

- MAXIMUM FILE-DESCRIPTOR USE.
- DEEPEST VFS AND FILESYSTEM CALL PATHS.
- PIPE BLOCK AND WAKEUP.
- TTY BLOCK AND WAKEUP.
- WAIT AND CHILD EXIT WAKEUP.
- SWAP OUT AND RESUME WITH A SLEEPING EXECUTIVE CONTINUATION.
- USER-EXTENT COMPACTION WHILE OTHER PROCESSES RETAIN EXECUTIVE AREAS.
- REPEATED FORK/EXEC/EXIT TO CATCH STALE EXECUTIVE-AREA STATE.
- STACK WATERMARK OR CANARY TESTS THAT FAIL BEFORE ANY OUT-OF-BOUNDS WRITE.

### 8. MEASUREMENT AND ACCEPTANCE

REPORT ALL SIZES IN BOTH OCTAL PDP-10 WORDS AND DECIMAL WORDS.

FOR EACH PROPOSED LAYOUT RECORD:

- FIXED CONTEXT WORDS.
- CWD WORDS.
- FILE-DESCRIPTOR WORDS.
- KERNEL-STACK WORDS.
- TOTAL WORDS PER ACTIVE PROCESS.
- WORDS SAVED PER PROCESS.
- MAXIMUM TESTED STACK USE.
- SAFETY MARGIN.
- EXECUTION-SPEED EFFECT.

ACCEPT A SMALLER EXECUTIVE AREA ONLY WHEN:

- EVERY WORD IS ACCOUNTED FOR.
- STATIC AND DYNAMIC STACK ANALYSIS AGREE WITHIN AN EXPLAINED MARGIN.
- ALL SLEEP/WAKE, SWAP, COMPACTION, FORK, EXEC, AND EXIT TESTS PASS.
- NO ASSEMBLER OR COMPILER REGRESSION IS INTRODUCED.
- NO NEW COMMON-CASE TRAP OR COPY OVERHEAD IS INTRODUCED JUST TO SAVE RAM.
- THE SAVING IS REAL RESIDENT MEMORY, NOT MOVED INTO ANOTHER PER-PROCESS AREA.

### 9. FOLLOW-UP OPTIMIZATION ORDER

AFTER THE EXECUTIVE-AREA CENSUS, CONTINUE IN THIS ORDER:

1. REMOVE UNUSED OR MISNAMED CONTEXT RESERVATIONS.
2. RIGHT-SIZE THE PRIVATE KERNEL STACK.
3. PACK THE FILE-DESCRIPTOR TABLE IF THE CENSUS SUPPORTS IT.
4. PACK OR DERIVE CWD AND OTHER SMALL PER-PROCESS STATE.
5. RE-CENSUS TOTAL RESIDENT MEMORY PER ACTIVE PROCESS.
6. ONLY THEN CONSIDER SELECTIVE PDP-10 ASSEMBLY FOR REMAINING STRUCTURAL COSTS.

## 10. SWAP RECORD STRUCTURAL SHARING

PERFORM A THOROUGH INSPECTION OF THE THREE-WORD PER-PROCESS SWAP RECORD.
DO NOT ASSUME THAT ALL THREE WORDS ARE INHERENTLY SWAP STATE.

THE CURRENT LOGICAL CONTENT IS:

- BACKING EXECUTABLE VNODE.
- IMAGE SPAN, INCLUDING PURE FLAG, TEXT SIZE, AND IMAGE SIZE.
- DISK SPAN, PACKING FIRST SWAP BLOCK AND SWAP BLOCK COUNT INTO ONE WORD.

THE DISK-SPAN WORD IS THE ACTUAL CURRENT SWAP-ALLOCATION STATE.  IT ALREADY
ENCODES BOTH WHETHER A PROCESS HAS A LIVE SWAP ALLOCATION AND WHERE THAT
ALLOCATION IS LOCATED.

INVESTIGATE WHETHER THE OTHER TWO WORDS ARE REALLY SWAP-SPECIFIC OR DUPLICATE
PROCESS OR EXECUTABLE METADATA.

- TRACE EVERY USER OF THE BACKING VNODE.
- TRACE EVERY USER OF PURE FLAG, TEXT SIZE, AND IMAGE SIZE.
- DETERMINE WHETHER THESE VALUES ALREADY EXIST IN PROCESS, EXEC, VFS, OR MM
  STATE OR CAN BE DERIVED WITHOUT ADDING HOT-PATH COST.
- PRESERVE THE PURE-TEXT OPTIMIZATION: CLEAN TEXT MUST REMAIN RELOADABLE FROM
  THE EXECUTABLE WITHOUT WRITING IT TO SWAP.
- DETERMINE WHETHER EXECUTABLE RECONSTRUCTION METADATA CAN BE SHARED WITH THE
  PROCESS EXECUTION STATE INSTEAD OF BEING DUPLICATED IN THE SWAP TABLE.
- DETERMINE WHETHER A PROCESS THAT HAS NEVER SWAPPED NEEDS ANY DEDICATED SWAP
  RECORD OTHER THAN A ZERO DISK-SPAN WORD.
- PRESERVE THE CURRENT LOW-RAM ALLOCATION STRATEGY UNLESS A BETTER ONE IS
  PROVEN: SCANNING PROCESS DISK-SPAN WORDS IS PREFERABLE TO ADDING A LARGE
  SWAP BITMAP OR FREE-LIST ONLY TO SAVE CPU TIME.
- DO NOT INTRODUCE CUMULATIVE READ/WRITE ACCOUNTING.  SWAP STATE MUST DESCRIBE
  CURRENT CAPACITY AND CURRENT ALLOCATIONS, NOT HISTORICAL I/O ACTIVITY.

TARGET THE FOLLOWING QUESTION EXPLICITLY:

CAN THE PER-PROCESS SWAP TABLE BE REDUCED FROM THREE WORDS PER SLOT TO ONE
WORD PER SLOT, WITH EXECUTABLE RECONSTRUCTION METADATA STORED ONCE ELSEWHERE
OR DERIVED FROM EXISTING AUTHORITATIVE STATE?

FOR EACH DESIGN, REPORT:

- WORDS PER PROCESS SLOT.
- TOTAL RESIDENT WORDS AT 64, 128, AND 256 PROCESS SLOTS.
- ADDITIONAL LOOKUPS OR INSTRUCTIONS ON SWAP-OUT AND SWAP-IN.
- WHETHER PURE EXECUTABLE TEXT CAN STILL BE RELOADED DIRECTLY.
- WHETHER ANY STATE IS DUPLICATED ELSEWHERE.
- WHETHER THE DESIGN REQUIRES A NEW BITMAP, FREE-LIST, OR ALLOCATION TABLE.

PREFER ONE WORD PER PROCESS WHEN IT CAN REPRESENT THE COMPLETE CURRENT SWAP
ALLOCATION WITHOUT DUPLICATING EXECUTABLE METADATA OR SLOWING NORMAL PROCESS
EXECUTION.
