THE SEPARATE PERMANENT IDLE/EXIT STACK IS NOW 0100 OCTAL WORDS, 64 DECIMAL.  THE EARLIER 0500-OCTAL REQUIREMENT WAS DOMINATED BY LATE KINIT, NOT RUNTIME IDLE USE.  LATE KINIT NOW STAYS ON THE DISPOSABLE KINIT RESERVE UNTIL ALL ALLOCATING/VFS WORK IS FINISHED AND PUBLISHES THE PERMANENT STACK ONLY AT THE FINAL NO-RETURN USER HANDOFF. ### 3. INSPECT SLEEPING CONTINUATIONS

OPTIMIZE THIS REQUIREMENT WITHOUT WEAKENING IT.

- PROVE WHICH STACK FRAMES MAY BE LIVE ACROSS PROC_WAIT_EVENT.

### 4. INSPECT FILE-DESCRIPTOR RESIDENT COST COMPLETE

THE 13 FILE DESCRIPTORS ARE NOW TWO WORDS EACH.  THE FULL 36-BIT CHARACTER OFFSET IS PRESERVED.

- WORD 0 PACKS THE CANONICAL VNODE AND DESCRIPTOR METADATA.
- WORD 1 IS THE UNCHANGED 36-BIT CHARACTER OFFSET.
- CURRENT VNODE PROVIDERS, MOUNT IDS, AND LOCAL KINDS USE ONLY THE LOW THREE BITS OF THEIR SIX-BIT FIELDS.  THE NINE OTHERWISE-ZERO HIGH BITS CARRY READ, WRITE, DIRECTORY, FOUR-BIT DUP/LOCK-FAMILY IDENTITY, AND TWO-BIT REGULAR/SHARED/EXCLUSIVE STATE.
- APPEND, CREATE, AND TRUNCATE ARE OPEN-TIME BEHAVIOR AND ARE NOT RETAINED IN THE DESCRIPTOR.
- THE REGULAR/LOCK FIELD IS MULTIPLEXED: ZERO MEANS NON-REGULAR, 01 REGULAR UNLOCKED, 10 SHARED, AND 11 EXCLUSIVE.
- DUP COPIES BOTH DESCRIPTOR WORDS VERBATIM, WHICH PRESERVES OFFSET AND LOCK-FAMILY SEMANTICS.
- HOT VFS PATHS RECOVER THE CANONICAL VNODE WITH ONE LEFT-HALF MASK; THE CHARACTER OFFSET IS NEVER PACKED OR TRUNCATED.
- FILE_NEW_FD REJECTS ANY VNODE WHICH ALREADY USES A METADATA-HOLE BIT.  A FUTURE VNODE NAMESPACE EXPANSION THEREFORE FAILS CLOSED AND REQUIRES AN EXPLICIT DESCRIPTOR-LAYOUT REDESIGN.

THE FIRST GENERAL C/TABLE PROTOTYPE COST 88 FIXED KCORE WORDS AND WAS REJECTED.  SELECTIVE PDP-10 ASSEMBLY FOR CLOSE, DUP, AND FLOCK REDUCED THE ACCEPTED FIXED COST TO 8 WORDS INCLUDING THE VNODE-RANGE GUARD.  THE U-AREA SAVES 13 WORDS FOR EACH ACTIVE PROCESS.

NET PHYSICAL RAM SAVING IS THEREFORE 5 WORDS WITH ONE ACTIVE PROCESS, 18 WITH TWO, AND 57 WITH FIVE.  THE SAVING GROWS BY 13 WORDS FOR EACH ADDITIONAL ACTIVE PROCESS.

DAIMOS-TESTKIT PROVES THE TWO-WORD LAYOUT, A FULL-WIDTH 36-BIT OFFSET THROUGH DUP, LOCK-FAMILY SHARING, SHARED/EXCLUSIVE CONFLICTS, DESCRIPTOR REUSE, AND REJECTION OF A VNODE WHICH COLLIDES WITH PACKED METADATA.

DO NOT PACK THE CHARACTER OFFSET.  DO NOT WIDEN PROVIDER, MOUNT, OR LOCAL-KIND FIELDS INTO THE RESERVED HIGH BITS WITHOUT FIRST REDESIGNING THIS REPRESENTATION.

### 5. INSPECT CWD AND OTHER PER-PROCESS STATE COMPLETE

PID IS NO LONGER STORED IN THE THREE-WORD PROCESS DESCRIPTOR.  THE PROCESS-TABLE
SLOT IS THE PID AND PROCINFO RETURNS THAT SLOT DIRECTLY.  THIS REMOVES REDUNDANT
PID INITIALIZATION AND TWO FIXED KCORE WORDS FROM PROCINFO, WHILE LEAVING THE LOW
EIGHT BITS OF PROC.META FREE FOR FUTURE STRUCTURAL SHARING.

CWD REMAINS ONE WORD IN THE STABLE U-AREA.  THE CURRENT VNODE NAMESPACE CAN BE
LOSSLESSLY COMPRESSED TO 27 BITS: THREE BITS EACH FOR PROVIDER, MOUNT ID, AND
LOCAL KIND, PLUS THE 18-BIT FILE INDEX.  THE FREED PID BYTE ALONE IS THEREFORE
INSUFFICIENT.

PROCESS USER BASE AND ALLOCATED SIZE ARE BOTH 02000-OCTAL-WORD ALIGNED, SO THEIR
TWO HALFWORDS CONTAIN 20 GUARANTEED-ZERO LOW BITS.  TOGETHER WITH THE FREED PID
BYTE THIS IS ENOUGH BIT CAPACITY TO STORE CWD, BUT DOING SO WOULD SPLIT CWD
ACROSS THREE PROCESS-DESCRIPTOR FIELDS AND ADD MASK/RECONSTRUCTION WORK TO EVERY
RELATIVE PATH OPERATION.  THE CURRENT U-AREA REPRESENTATION PROVIDES CWD WITH A
SINGLE DIRECT LOAD IMMEDIATELY BEFORE FILE_TABLE.  DO NOT TRADE THAT HOT-PATH
SIMPLICITY FOR ONE WORD PER ACTIVE PROCESS WITHOUT A NEW MEASURED IMPLEMENTATION
THAT SHOWS A NET RAM AND EXECUTION BENEFIT.

NO UNUSED WHOLE WORD OR SAFE LIFETIME ALIAS EXISTS IN THE SAVED CONTEXT, FD
TABLE, OR CURRENT THREE-WORD PROCESS DESCRIPTOR.

## 10. SWAP RECORD STRUCTURAL SHARING

COMPLETED.

THE THREE-WORD PER-SLOT SWAP RECORD HAS BEEN REDUCED TO ONE WORD WITHOUT
ADDING A BITMAP, FREE LIST, OR SECOND RESIDENT EXECUTABLE-METADATA TABLE.

THE FINAL REPRESENTATION REUSES THE SAME WORD ACCORDING TO PROCESS RESIDENCY:

- RESIDENT PROCESS: PACKED EXECUTABLE BACKING + PURE-TEXT BOUNDARY.
- SWAPPED PROCESS: LH FIRST SWAP BLOCK + RH TOTAL SWAP BLOCK COUNT.

THE RESIDENT WORD FITS EXACTLY IN 36 BITS FOR THE CURRENT EXECUTABLE-CAPABLE
FILESYSTEM PROVIDERS:

- 18 BITS: FILE INDEX.
- 2 BITS: MOUNT ID MINUS ONE; CURRENT VFS MOUNT IDS ARE 1 THROUGH 4.
- 2 BITS: PROVIDER MINUS MEMFS_PROVIDER; MEMFS, DTFS, AND D6FS ARE 4, 5, 6.
- 14 BITS: PURE-TEXT WORD BOUNDARY.

THE LOCAL FILE KIND IS IMPLIED BY THE PROVIDER.  A ZERO TEXT BOUNDARY MEANS
THE PROCESS IS SWAPPED CONSERVATIVELY IN FULL; THIS ALSO COVERS A PURE IMAGE
WITH ZERO RELOADABLE TEXT WITHOUT REQUIRING A SEPARATE PURE FLAG.

WHEN SWAPPING OUT, DAIMOS WRITES ONE 0200-OCTAL-WORD HEADER BLOCK CONTAINING
THE RESIDENT PACKED WORD, FOLLOWED BY THE NON-RECONSTRUCTIBLE PROCESS DATA.
THE RESIDENT TABLE WORD THEN BECOMES THE DISK SPAN.  SWAP-IN READS THE HEADER,
RECONSTRUCTS THE BACKING VNODE, RELOADS CLEAN PURE TEXT WHEN THE TEXT BOUNDARY
IS NONZERO, RESTORES THE WRITABLE DATA, AND RESTORES THE PACKED RESIDENT WORD.

THIS KEEPS EXECUTABLE RECONSTRUCTION METADATA ON DISK ONLY WHILE A PROCESS IS
ACTUALLY SWAPPED.  IT DOES NOT ADD NORMAL EXECUTION LOOKUPS OR INSTRUCTIONS.
THE SWAP ALLOCATOR STILL SCANS THE PER-PROCESS DISK-SPAN WORDS; NO BITMAP OR
FREE LIST WAS ADDED.

MEASURED COST AND SAVING AGAINST THE PREVIOUS THREE-WORD DESIGN:

- FIXED KCORE COST: +54 WORDS.
- TABLE SAVING: 2 WORDS PER LOGICAL PROCESS SLOT.
- 64 SLOTS: 128 TABLE WORDS SAVED, 74 NET RESIDENT WORDS SAVED.
- 128 SLOTS: 256 TABLE WORDS SAVED, 202 NET RESIDENT WORDS SAVED.
- 256 SLOTS: 512 TABLE WORDS SAVED, 458 NET RESIDENT WORDS SAVED.
- DISK COST: ONE ADDITIONAL 0200-OCTAL-WORD HEADER BLOCK PER CURRENTLY SWAPPED
  PROCESS.

THE EARLIER IDEA OF REREADING AND PARSING THE DXR HEADER ON EVERY SWAP-OUT WAS
REJECTED: ITS C IMPLEMENTATION ADDED ABOUT 202 FIXED KCORE WORDS AND MADE THE
64-SLOT CONFIGURATION LARGER OVERALL.

FOLLOW-UP: DO NOT REOPEN THIS REPRESENTATION UNLESS A FUTURE EXECUTABLE-CAPABLE
VFS PROVIDER CANNOT BE REPRESENTED BY THE CURRENT PACKING.  SUCH A PROVIDER
MUST EITHER DEFINE AN EQUIVALENT COMPACT EXECUTABLE HANDLE OR JUSTIFY A NEW
REPRESENTATION WITH A FRESH RESIDENT-MEMORY CENSUS.

## 13. DTFS HEADER FIELDS AND D6FS DIRECTORY-ENTRY WRITER

COMPLETED.

DTFS_HEADER AND DTFS_HDR_NEXT ARE NOW EXPRESSION-LEVEL FIELD OPERATIONS IN THE
C SOURCE.  THE PDP-10 COMPILER PREVIOUSLY KEPT BOTH AS OUT-OF-LINE HELPERS, SO
EVERY BLOCK HEADER ENCODE/DECODE PAID A PUSHJ EVEN THOUGH THE TARGET OPERATION
IS ONLY AN LDB OR A SHORT SHIFT/OR SEQUENCE.  THE NEW FORM REMOVES THE HELPER
BODIES AND CALL OVERHEAD WITHOUT CHANGING THE MEDIA FORMAT OR VALIDATION.

D6FS_PROVIDER_WRITE_DIRENT AND D6FS_PROVIDER_FREE_FCB ARE NOW HAND-WRITTEN
PDP-10 ASSEMBLY FOR TARGET BUILDS, WITH THE C IMPLEMENTATIONS RETAINED FOR HOST
BUILDS.  ITS DIRECTORY
OFFSET AND FILE SIZE ARE BOUNDED BY VALIDATED D6FS GEOMETRY, SO THE TARGET
ROUTINE CAN USE THE DIRECT PDP-10 COMPARISON INSTEAD OF GCC'S GENERAL UNSIGNED
NORMALIZATION.  IT ALSO SAVES ONLY THE THREE AC'S THAT MUST LIVE ACROSS CALLS.
THE FIRST ASSEMBLY DRAFT EXPOSED BOTH A STACK-FRAME OVERLAP AND AN INVERTED
CAMG BRANCH; THE FULL D6FS MUTATION REGRESSION CAUGHT BOTH.  THE ACCEPTED
ROUTINE USES NON-OVERLAPPING FCB/INFO/DIRENT SCRATCH STORAGE AND PRESERVES THE
ORIGINAL RESIZE-ON-GROW CONDITION.
