# P0 v474: strict 32K link, KINIT, and native boot acceptance

This is an acceptance **failure report** from actual builds on
2026-10-27, not a P0 completion claim. P2 sizing/profiling work is
paused until the strict P0 gate has been met.

## Fresh GCC PDP-6 lowmem measurements

- Default linked profile: KCORE **8960** (`021400`), KCORE+MRES
  **15507**, PERMANENT_LAST **15554** words. KCORE must be strictly
  below **8192** (`020000`), so at least **769** words must be removed
  from that linked profile to meet the strict inequality.
- Explicit `ROOT=disk BOOT=dsk` and `ROOT=tape BOOT=dtc` footprint
  builds: both KCORE **9008** (`021460`), **816** at or above the
  forbidden boundary, requiring **817** fewer linked words to pass.
  (The reported +816 is the difference from the boundary, not the
  number necessary to be strictly below it.)
- Disk KINIT `074404`, leaving **764** words after a `02000`-word
  stack reserve; tape KINIT `075457`, leaving **209** words.
  These are footprint-only builds, not shell/boot acceptance.
- The existing `check-kcore-32k-v1.sh` correctly fails with
  `KCORE 32K FAIL: end 021460 >= 020000`.

## Actual 32K boot checks

The existing `daimos-low-memory-boot-v2.sh` default auto-root build
fails before simulation: `mkimage: KINIT image leaves less than the
configured stack reserve`. A retry with **ROOT=disk BOOT=dsk** gets
past image generation; SIMH runs KINIT and INIT and presents DCS0
LOGIN. Logging in as ROOT produces `LOGIN INCORRECT` and the script
fails before DSH/MEMSTAT/DATE. The login source treats account lookup
errors the same as unknown accounts; the actual failure inside that
lookup has not been isolated. Do not classify it as OOM without proof.

## P0 disposition

P0 is **OPEN**: shrink the measured default/single-root linked KCORE
below `020000`, retain ABI/FS/scheduler correctness, ensure KINIT plus
reserved stack and startup headroom, and pass the native 32K
LOGIN/DSH/pressure test with the same measured image. No relocation
of always-required resident code solely to conceal RAM cost. Continue
with measured large resident FILE/VFS/syscall and scheduler reductions
and testkit regressions; P2 profiling and dynamic sizing are skipped.

No production source was changed by this v474 measurement.
