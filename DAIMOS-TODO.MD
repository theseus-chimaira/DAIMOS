# DAIMOS VERSION 0.9 ROADMAP

THIS FILE DEFINES OPEN WORK REQUIRED TO REACH VERSION 0.9.  THE PREVIOUS
PRE-USERLAND ACCEPTANCE REMAINS THE BASELINE.  THE SCHEDULER AND MEMORY-MANAGER
WORK FROM THE PDP-6/JOSS HANDOFF, INCLUDING SWAP/COMPACTION PLANNING, IS
COMPLETE AND RECORDED IN STATUS.MD.  A REAL INIT IS THE REMAINING EXPLICIT
PRE-DSH GATE.

DO NOT BEGIN THE DSH IMPLEMENTATION PHASE UNTIL SECTION 7 BELOW HAS PASSED ITS
ACCEPTANCE TESTS.

## COMPLETED PRE-DSH OPTIMIZATION GATES

THE SCHEDULER CENSUS, INTRUSIVE RUN QUEUE, QUANTUM FAST PATH, COARSE
ACCOUNTING, MM DESCRIPTOR CENSUS, AND ALLOCATED-EXTENTS-ONLY MM EXPERIMENT ARE
COMPLETE.  THEIR CURRENT DESIGN, MEASUREMENTS, AND ACCEPTANCE RESULTS ARE IN
STATUS.MD.

## 7. REAL INIT BEFORE DSH

IMPLEMENT A REAL, SEPARATE USERLAND `/SYSTEM/INIT` BEFORE DSH DEVELOPMENT
CONTINUES.  THE CURRENT BOOT MAKEFILE INSTALLS `$(DSH_DXR)` AS `/SYSTEM/INIT`;
THAT TEMPORARY ALIAS MUST BE REMOVED.

THE VERSION 0.9 INIT SHOULD BE SMALL AND PURPOSEFUL:

- BUILD A DISTINCT INIT EXECUTABLE AND INSTALL IT AS `/SYSTEM/INIT`.
- KEEP INIT AS THE FIRST USER PROCESS/PID 1 AND THE ORPHAN REAPER.
- ESTABLISH THE INITIAL SESSION, DOMAIN, PROCESS GROUP, FOREGROUND TTY, AND
  CTY DESCRIPTOR STATE EXPLICITLY.
- LAUNCH `/SYSTEM/DSH` AS A CHILD WITH STDIN/STDOUT/STDERR MAPPED TO CTY.
- REAP ALL CHILDREN AND ADOPTED ORPHANS SO ZOMBIES CANNOT ACCUMULATE.
- WHEN THE PRIMARY CONSOLE DSH EXITS, REAP IT AND RESPAWN A FRESH CONSOLE DSH.
- KEEP INIT INDEPENDENT OF DSH BUILTINS AND COMMAND-PARSER INTERNALS.
- DO NOT ADD A GENERAL SERVICE MANAGER, RC LANGUAGE, OR CONFIGURATION SYSTEM
  FOR VERSION 0.9 UNLESS A CONCRETE BOOT REQUIREMENT APPEARS.

TEST AT LEAST:

- `/SYSTEM/INIT` AND `/SYSTEM/DSH` ARE DISTINCT IMAGES.
- BOOT ENTERS INIT AS THE FIRST USER PROCESS.
- INIT LAUNCHES DSH WITH THE EXPECTED SESSION/PGRP/TTY STATE.
- DSH EXIT IS REAPED AND DSH IS RESPAWNED.
- ORPHANED CHILDREN ARE ADOPTED AND REAPED BY INIT.
- REPEATED SHELL EXIT/RESPAWN DOES NOT LEAK PROCESS SLOTS, FILE DESCRIPTORS,
  U-AREAS, OR SWAP BACKING.
- STOP/CONT/JOB-CONTROL OPERATIONS ON DSH DO NOT STOP INIT.

ONLY AFTER SECTION 7 PASSES IS DSH THE NEXT IMPLEMENTATION PHASE.

## 8. PRESERVE THE KERNEL ABI FOUNDATION

- KEEP KCC AND GCC CALLING CONVENTIONS ABI COMPATIBLE.
- KEEP EXECUTIVE INTERNAL SERVICE CALLS ON DIRECT REGISTER BRIDGES UNLESS
  MEASUREMENT PROVES A DIFFERENT ABI SMALLER AFTER TRAP COST IS INCLUDED.
- KEEP COMMON VFS, MRES, DEVICE, AND SERVICE DISPATCH PATHS SHARED.
- FIX ASSEMBLER OR COMPILER DEFECTS AT THEIR SOURCE BEFORE LOWER-PRIORITY WORK.

## 9. COMPLETE DSH FOR DAILY USE

- USE THE EXISTING DAIMOSV1 DSH IMPLEMENTATION AS THE STARTING POINT.
- COMPLETE PIPELINE EXECUTION, REDIRECTION, PROCESS GROUPS, FOREGROUND AND
  BACKGROUND CONTROL, AND BUILTINS REQUIRED FOR BOOTSTRAP/ADMINISTRATION.
- INTEGRATE THE GETOPT HELP/MANUAL-PAGE MODEL AND THE DEFERRED STRUCTURED
  COMPLETION INTERFACE WITHOUT DUPLICATING COMMAND METADATA.
- KEEP PARSING SMALL AND PURPOSEFUL.

## 10. PORT MAKE AND ITS DEPENDENCIES

- PORT THE MINIMUM MAKE IMPLEMENTATION AND SUPPORT UTILITIES REQUIRED FOR
  NATIVE BUILDS.
- REMOVE HOST-ONLY ASSUMPTIONS FROM THE DAIMOS BUILD PATH.
- VERIFY A NATIVE EDIT/BUILD/INSTALL CYCLE BEFORE EXPANDING FEATURES.

## 11. PORT DAS

- BUILD DAS NATIVELY AFTER THE MINIMUM MAKE ENVIRONMENT WORKS.
- VERIFY ASSEMBLY AND LINKING OF REPRESENTATIVE USER AND SYSTEM OBJECTS.
- FIX DAS OR LINKER DEFECTS PROPERLY; DO NOT ADD DAIMOS-SPECIFIC WORKAROUNDS.

## 12. PORT ELVIS AND THE PRACTICAL USER TOOLSET

- COMPLETE THE FEATURE-RICH ELVIS VI/EX PORT WITH SPELLING AND FOLDING.
- KEEP SYNTAX HIGHLIGHTING, COLORS, URL FEATURES, AND NON-SIXBIT RECORD
  FEATURES OUT OF THE PORT.
- PROVIDE THE BASIC FILE, DIRECTORY, TEXT, COPY, MOVE, REMOVE, AND SYSTEM
  INSPECTION UTILITIES REQUIRED FOR DAILY USE AND SELF HOSTING.

## 13. PREPARE AND PORT KCC

- VERIFY KCC/GCC ABI INTEROPERABILITY WITH MIXED OBJECTS.
- SWITCH THE MAIN DAIMOS COMPILER TO KCC TEMPORARILY WHEN THE NATIVE TOOL PATH
  IS READY, SO ABI AND CODE-GENERATION DEFECTS ARE FOUND EARLY.
- PORT THE REQUIRED KCC FRONT END, BACK END, LIBRARY SUPPORT, AND BUILD RULES.
- BUILD KCC UNDER DAIMOS AND VERIFY ITS OUTPUT WITH DAS AND GCC OBJECTS.

## 14. REVISIT USERSPACE OVERLAYS AFTER MEASUREMENT

USERSPACE OVERLAYS ARE NOT A PRE-DSH OR INITIAL SELF-HOSTING GATE.  MEASURE
NATIVE DAS AND ELVIS FIRST.  ONLY THEN DECIDE WHETHER AN OVERLAY ABI IS
JUSTIFIED.  FOLLOW PDP10-DOC KERNEL/MEMORY-MANAGEMENT.MD AND
KERNEL/SELFHOSTING.MD.

## 15. ADD THE RUNTIME MODULE LOADER

THIS REMAINS AFTER THE INITIAL USER ENVIRONMENT AND SELF-HOSTING PORT.

- LOAD MOVABLE MODULES INTO MANAGED CORE.
- APPLY RELOCATION AND SERVICE BINDINGS.
- COMPACT MOVABLE MODULES WITH THE MEMORY MANAGER.
- LOAD SLOW DEVICE SUPPORT ON DEMAND WHERE APPROPRIATE.
- AUTO-UNLOAD AUTOMATICALLY LOADED MODULES AFTER THEIR LAST HANDLE IS RELEASED.
- KEEP MANUALLY LOADED MODULES RESIDENT UNTIL EXPLICITLY UNLOADED.
- VERIFY FAILURE AT EVERY LOAD, RELOCATION, BIND, MOVE, AND UNLOAD BOUNDARY.

## 16. VERSION 0.9 VALIDATION

- RUN MULTIUSER SCHEDULER, PIPE, FILE-DESCRIPTOR, COMPACTION, AND SWAP STRESS.
- RUN D6FS AND DTFS MUTATION, RECOVERY, MEDIA-FULL, AND STORAGE-ERROR TESTS.
- RUN MODULE MOVE/UNLOAD STRESS AFTER THE LOADER EXISTS.
- MEASURE INTERACTIVE LATENCY ON PDP-6 CLASS HARDWARE OR SIMULATION.
- KEEP KCORE PLUS NORMAL FULL-BOOT MRES WITHIN THE DOCUMENTED RESIDENT LIMIT OR
  EXPLICITLY REVISE THAT LIMIT BEFORE ACCEPTING REQUIRED KERNEL FUNCTIONALITY.
- REQUIRE CLEAN DAIMOS, DAIMOS-TESTKIT, DAS, KCC, AND PDP10-TOOLS REGRESSIONS.
- REQUIRE NO KNOWN COMPILER OR ASSEMBLER BUG AFFECTING GENERATED SYSTEM CODE.

## 17. NOT PART OF VERSION 0.9

NETWORKING IS COMPLETELY DEFERRED.  DO NOT IMPLEMENT OR PORT A NETWORK STACK,
NETWORK PROTOCOLS, NETWORK USER UTILITIES, OR NETWORK-DEPENDENT SERVICES AS A
VERSION 0.9 REQUIREMENT.

SOCKETS ARE NOT CURRENTLY A VERSION 0.9 REQUIREMENT EITHER.  THEIR API,
SEMANTICS, RELATIONSHIP TO FILE DESCRIPTORS, AND TARGET VERSION MUST BE
DISCUSSED SEPARATELY BEFORE ANY SOCKET ABI IS ADDED.

THE COMPACT TIMER/EVENT MODEL FROM THE PDP-6/JOSS HANDOFF REMAINS A DESIGN
REFERENCE FOR A FUTURE FEATURE WHICH ACTUALLY NEEDS GENERAL TIMERS.  DO NOT
ADD A GENERAL TIMER SUBSYSTEM NOW MERELY IN ANTICIPATION OF NETWORKING.
