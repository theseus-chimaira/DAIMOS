# DAIMOS

DAIMOS IS A SMALL MULTIUSER OPERATING SYSTEM FOR THE PDP-6 AND COMPATIBLE
PDP-10 MACHINES.  THE MINIMUM/INITIAL MACHINE IS A 32K-WORD PDP-6.

FOR CURRENT DEVELOPMENT STATE AND ORDER, READ PROJECT-STATE.MD FIRST.  OPEN
WORK IS IN TODO.MD; STATUS.MD SUMMARIZES THE IMPLEMENTED TREE.  DETAILED DESIGN
DOCUMENTATION LIVES IN THE PDP10-DOC REPOSITORY.

## CORE DESIGN

THE PROCESS MODEL USES A SMALL FIXED DESCRIPTOR AND A STABLE EXECUTIVE AREA.
USER EXTENTS MAY MOVE DURING COMPACTION OR LEAVE CORE DURING SWAPPING WHILE THE
EXECUTIVE CONTINUATION REMAINS RESIDENT.  THE GENERIC VM INTERFACE HIDES THIS
PDP-6 REPRESENTATION SO A LATER MACHINE-SPECIFIC PAGER BACKEND CAN REPLACE IT.

DISK/DRUM I/O IS ASYNCHRONOUS FROM THE PROCESS PERSPECTIVE.  STORAGE SETS
EXPORT LOGICAL BLOCKS; PHYSICAL DISTRIBUTION, DEVICE SCHEDULING, AND BAD-MEDIA
MAPPING STAY BELOW FILESYSTEMS.

VFS PROVIDES COMMON PATH, MOUNT, DESCRIPTOR, AND ACCESS-CHECKING MECHANISMS.
D6FS IS THE NATIVE WRITABLE DISK FILESYSTEM.  PIPES/FIFOS ARE COMPACT NATIVE
KERNEL IPC OBJECTS.  PROCESS GROUPS, SESSIONS, DOMAINS, CONTROLLING TERMINALS,
STOP/CONTINUE, AND NATIVE PROCESS EVENTS ARE IMPLEMENTED KERNEL STATE.

## MEMORY BUDGET

THE HARD ARCHITECTURAL KERNEL LIMIT IS BELOW 16K WORDS INCLUDING ALL RESIDENT
AND SCRATCH KERNEL MEMORY.  THE CURRENT 14K SHRINK GATE IS:

    KCORE + MRES <= 14288 DECIMAL WORDS

THE CURRENT KCC BUILD WITH THE COMPLETED DSH PLATFORM PREREQUISITES,
RECLAIMABLE D6FS CACHE, LPT SUPPORT, AND THE DIRECT-SLIDE COMPACTOR IS 15678
KCORE+MRES WORDS WITH PERMANENT_LAST 036555.  THE 14288-WORD SHRINK GATE IS
CURRENTLY ADVISORY DURING
EARLY USERSPACE/KERNEL-STABILIZATION WORK; THE HARD BELOW-16K RESIDENT+SCRATCH
LIMIT REMAINS ABSOLUTE.  KCC IS THE ACCEPTANCE COMPILER; GCC SIZE RESULTS ARE
COMPARISON DATA ONLY.

## USERSPACE AND TOOLCHAIN

THE NORMAL BOOT ENTERS /SYSTEM/INIT AS PID 1.  INIT READS /CONFIG/INITTAB AND
STARTS LOGIN PROCESSES.  LOGIN AUTHENTICATES AGAINST /CONFIG/PASSWD AND EXECUTES
THE CONFIGURED SHELL, INITIALLY /SYSTEM/EXEC/DSH.

KCC IS THE REQUIRED NORMAL C COMPILER FOR BOTH KERNEL AND USERSPACE, AND
CURRENT NORMAL USERSPACE BUILDS WITH KCC/DAS WITHOUT LIBGCC.  THE RUN/EXEC
STARTUP ABI, DUP2-EQUIVALENT OPERATION, TTY LINE DISCIPLINE, ISATTY, UMASK, LOGIN
ENVIRONMENT, RECLAIMABLE D6FS CACHE, PDP-6 LPT SUPPORT, AND THE DIRECT-SLIDE
MM COMPACTOR/RELOCATOR ARE IMPLEMENTED.  BEFORE SUBSTANTIAL DSH WORK, COMPLETE
MONITORFS + /DEV CONSOLIDATION AND CLOSE THE SMALL FILESYSTEM/SYSCALL SET THAT
DAIMOSV1 USERLAND ANALYSIS SHOWS IS ACTUALLY NEEDED: SEEK, CHOWN, DIRECTORY
REMOVAL, AND MTIME/STAT/TOUCH.  THEN IMPLEMENT DSH, PORT THE REQUIRED CORE
UTILITIES, AND CONTINUE WITH MAKE, DAS/DLINK/DARC, AND NATIVE KCC.

## FILESYSTEM AND STORAGE DIRECTION

D6FS WILL OWN OPTIONAL SWAP AND LOGSTORE LOGICAL RESERVATIONS.  THEY ARE NOT
FILES; VFS REGISTERS THEIR RAW BACKING RANGE AND ACTIVE I/O GOES DIRECTLY
THROUGH THE LOWER BLOCK/DISKSET PATH.  THE DISKSET LAYER CHOOSES PHYSICAL
DISTRIBUTION.

THE CURRENT IMPLEMENTATION STILL CONTAINS THE OLDER DISKSET-OWNED SEMANTIC
SWAP/LOGSTORE REGION FIELDS; PROJECT-STATE.MD AND PDP10-DOC DEFINE THE
MIGRATION.

THE CURRENT TREE ALSO STILL CONTAINS LEGACY DEVFS/PROCFS/DOMAINFS VIEWS.  THE
ACCEPTED PRE-DSH DESIGN CONSOLIDATES KERNEL STATE UNDER /MONITOR AND PROVIDES
/DEV AS AN I/O-ONLY ALTERNATE VIEW OF THE SAME MONITORFS IMPLEMENTATION.  THERE
IS NO FUTURE /PROC VIEW.

## FULL PDP-6 BOOT

`MAKE BOOT` BUILDS THE NORMAL PDP-6 CONFIGURATION WITH THE NATIVE DTFS
PERSONALITY.  TENEX/ITS DTFS PERSONALITIES ARE EXPLICIT TEST OPTIONS RATHER
THAN PART OF THE NORMAL RESIDENT BUILD.  CTY IS LOCAL; THE SIMULATOR MAY EXPOSE
ADDITIONAL SERIAL TERMINAL LINES THROUGH HOST FACILITIES.  /CONFIG/INITTAB
STARTS THE CONFIGURED LOGIN PROCESSES.

THE CURRENT LEGACY DEVICE NAMESPACE IS STILL USED BY EXISTING TOOLS UNTIL THE
MONITORFS /DEV MIGRATION IS IMPLEMENTED.  DO NOT TREAT THAT LEGACY PATH AS THE
FUTURE VFS DESIGN.
