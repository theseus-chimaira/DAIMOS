# DAIMOS

DAIMOS IS A SMALL MULTIUSER OPERATING SYSTEM FOR THE PDP-6 AND COMPATIBLE PDP-10 MACHINES.

## DESIGN

DAIMOS USES A SMALL PERMANENT KERNEL WITH RECLAIMABLE INITIALIZATION CODE AND MOVABLE RUNTIME MODULES.

THE PROCESS MODEL USES A SMALL FIXED DESCRIPTOR AND A STABLE EXECUTIVE AREA.  USER EXTENTS MAY MOVE DURING COMPACTION OR LEAVE CORE DURING SWAPPING.  THE EXECUTIVE AREA STAYS RESIDENT SO A SLEEPING KERNEL CONTINUATION DOES NOT DEPEND ON A MOVABLE USER EXTENT.  THE SEPARATE PERMANENT IDLE/FINAL-EXIT STACK IS 0100 OCTAL WORDS; LATE KINIT REMAINS ON ITS DISPOSABLE RESERVE STACK UNTIL THE FINAL USER HANDOFF SO BOOT-TIME CALL DEPTH DOES NOT DETERMINE PERMANENT IDLE-STACK SIZE.

THE MEMORY MANAGER USES PHYSICAL EXTENTS, COMPACTION, AND EXPLICIT OWNERSHIP.  MOVABLE PROCESSES AND MOVABLE MODULES MAY BE RELOCATED TO CREATE CONTIGUOUS FREE CORE.

SWAPPING IS PROCESS ORIENTED.  CLEAN EXECUTABLE TEXT MAY BE RECREATED FROM ITS BACKING FILE.  ONLY STATE WHICH CANNOT BE RECREATED MUST BE WRITTEN TO SWAP.  EACH LOGICAL PROCESS SLOT USES ONE RESIDENT SWAP WORD: IT HOLDS A COMPACT EXECUTABLE HANDLE WHILE RESIDENT AND THE CURRENT DISK SPAN WHILE SWAPPED; THE EXECUTABLE HANDLE IS SAVED IN A SWAP HEADER BLOCK ONLY WHILE THE PROCESS IS OUT OF CORE.


THE VFS PROVIDES A COMMON INTERFACE FOR MEMORY FILES, DEVICE FILES, DECTAPE FILESYSTEM PERSONALITIES, AND D6FS.  FILESYSTEM SERVICE CODE SHOULD SHARE COMMON RESIDENT PATHS INSTEAD OF DUPLICATING DISPATCH AND TRANSFER LOGIC.

PER-PROCESS FILE DESCRIPTORS USE TWO WORDS: ONE FULL 36-BIT CHARACTER OFFSET AND ONE PACKED VNODE/STATE WORD.  THE PACKING USES ONLY BITS WHICH ARE ZERO FOR THE CURRENT PROVIDER, MOUNT, AND LOCAL-KIND RANGES; OPEN REJECTS VNODE VALUES WHICH WOULD COLLIDE WITH THOSE STATE BITS.

USER MONITOR UUOS FORM THE USER TO KERNEL ABI.  EXECUTIVE INTERNAL SERVICES USE DIRECT REGISTER CALLS RATHER THAN TAKING A SECOND UUO TRAP.  USER ABI UUOS SHOULD BE DIRECTLY USABLE FROM C WITH MINIMAL VENEER OVERHEAD.

SLOW OR OPTIONAL SUBSYSTEMS MAY EVENTUALLY BE LOADABLE MODULES.  MODULES WHICH ARE LOADED AUTOMATICALLY FOR A RESOURCE MAY BE UNLOADED AFTER THE LAST USER RELEASES THAT RESOURCE.  MANUALLY LOADED MODULES REMAIN RESIDENT UNTIL MANUALLY UNLOADED.

## USER ENVIRONMENT

THE USER ENVIRONMENT IS KEPT UNDER THE USR SOURCE TREE.  LIBC, DSH, COMMAND SUPPORT, AND FUTURE SELF-HOSTING TOOLS BELONG THERE.

THE LONG TERM USER ENVIRONMENT IS INTENDED TO PROVIDE ENOUGH OF A UNIX-LIKE TOOL MODEL FOR INTERACTIVE USE AND SELF HOSTING WITHOUT IMPORTING LARGE ABSTRACTIONS WHICH DO NOT PAY FOR THEIR RESIDENT COST.

THE TARGET SELF-HOSTING TOOLCHAIN INCLUDES DSH, MAKE, DAS, KCC, AND THEIR REQUIRED SUPPORT TOOLS.

## FILESYSTEMS

DAIMOS SUPPORTS ITS OWN D6FS AND DECTAPE FILESYSTEM PERSONALITIES.  D6FS IS A NORMAL WRITABLE FILESYSTEM.

TRANSFER REPRESENTATION SHOULD BE SHARED BETWEEN FILESYSTEMS WHERE POSSIBLE.  FORMAT PERSONALITIES SHOULD SHARE IMPLEMENTATION WHEN THE ON-MEDIA DIFFERENCE DOES NOT REQUIRE SEPARATE RESIDENT LOGIC.

## PORTABILITY AND ABI

THE SYSTEM IS DEVELOPED FOR PDP-6 AND PDP-10 EXECUTION AND IS BUILT WITH A CROSS TOOLCHAIN DURING HOST DEVELOPMENT.

KCC AND GCC GENERATED CODE MUST REMAIN ABI COMPATIBLE.  ABI CHANGES MUST BE MADE AT THE SYSTEM BOUNDARY RATHER THAN BY ADDING COMPILER-SPECIFIC WORKAROUNDS.

## FULL PDP-6 BOOT

`make boot` builds the normal PDP-6 kernel configuration with the NATIVE DTFS
personality resident.  TENEX and ITS remain build-time options and are enabled
explicitly by the testkit for foreign-personality validation; they are not
resident in the normal boot.  All implemented SIMH devices are enabled, three
DECtape and two magtape transports are attached, and the D6FS boot image
pre-creates `/MOUNT/DT0`, `/MOUNT/DT1`, and `/MOUNT/DT2`.

For diagnostic foreign-personality builds use `DTFS_TENEX=1 DTFS_ITS=1`.

DSH accepts `MOUNT` as the normal DTFS mount command; `MOUNT.DTFS` remains as a
compatibility spelling.  For example:

    MKFS.DTFS -O NATIVE /DEVICE/DTC0
    MOUNT /DEVICE/DTC0 /MOUNT/DT0
    LS /MOUNT/DT0
    UNMOUNT /MOUNT/DT0

The PDP-6 disk boot makefile also provides `make permanent-size`.  It reports
KCORE plus every MRES package installed by the normal full-hardware boot,
excluding KINIT/INIT and process-private storage.
