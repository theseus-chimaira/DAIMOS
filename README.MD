# DAIMOS

DAIMOS IS A SMALL MULTIUSER OPERATING SYSTEM FOR THE PDP-6 AND COMPATIBLE
PDP-10 MACHINES.  THE MINIMUM/INITIAL MACHINE IS A 32K-WORD PDP-6.

FOR CURRENT DEVELOPMENT STATE AND ORDER, READ PROJECT-STATE.MD FIRST.  OPEN
WORK IS IN TODO.MD; STATUS.MD SUMMARIZES THE IMPLEMENTED TREE.  DETAILED DESIGN
DOCUMENTATION LIVES IN THE PDP10-DOC REPOSITORY.

## CORE DESIGN

THE PROCESS MODEL USES A SMALL FIXED DESCRIPTOR AND A STABLE EXECUTIVE AREA.
USER EXTENTS MAY MOVE DURING COMPACTION OR LEAVE CORE DURING SWAPPING WHILE THE
EXECUTIVE CONTINUATION REMAINS RESIDENT.  THE GENERIC VM INTERFACE HIDES THIS
PDP-6 REPRESENTATION SO A LATER MACHINE-SPECIFIC PAGER BACKEND CAN REPLACE IT.

DISK/DRUM I/O IS ASYNCHRONOUS FROM THE PROCESS PERSPECTIVE.  STORAGE SETS
EXPORT LOGICAL BLOCKS; PHYSICAL DISTRIBUTION, DEVICE SCHEDULING, AND BAD-MEDIA
MAPPING STAY BELOW FILESYSTEMS.  DISKS AND DRUMS SHARE ONE COMPACT BAD-MEDIA
EXCEPTION-MAP FORMAT/TRANSLATOR; DEVICE-SPECIFIC RETRY AND ADDRESSING STAY IN
THE PHYSICAL DRIVERS.

VFS PROVIDES COMMON PATH, MOUNT, DESCRIPTOR, AND ACCESS-CHECKING MECHANISMS.
D6FS IS THE NATIVE WRITABLE DISK FILESYSTEM.  PIPES/FIFOS ARE COMPACT NATIVE
KERNEL IPC OBJECTS.  PROCESS GROUPS, SESSIONS, CONTROLLING TERMINALS,
STOP/CONTINUE, AND NATIVE PROCESS EVENTS ARE IMPLEMENTED KERNEL STATE.

## MEMORY BUDGET

THE HARD PERMANENT KERNEL LIMIT IS ADDRESSING BELOW 040000.  KCC IS USED FOR
THE OFFICIAL SIZE MEASUREMENT; GCC SIZE RESULTS ARE COMPARISON DATA ONLY.

KCORE IS THE FIXED RESIDENT KERNEL CORE THAT REMAINS AFTER BOOT.  KINIT IS THE
TRANSIENT INITIALIZATION IMAGE THAT DISCOVERS HARDWARE AND THE ROOT FILESYSTEM,
INSTALLS THE REQUIRED RESIDENT SERVICES, STARTS `/SYSTEM/INIT`, AND IS THEN
RECLAIMED.  MRES IS A MODULE'S RESIDENT PACKAGE: THE CODE AND SMALL STATE THAT
MUST REMAIN AFTER ITS INITIALIZATION ROUTINE HAS FINISHED.  THE CURRENT BUILD
HAS RESIDENT PACKAGES FOR CTY, CLK, PTR, PTP, CR, CP, DCS, GE, DPY, TTY,
WCNSLS, OCNSLS, DSK, TAPE, SLV, DRM, MEMFS, DTFS/TSFS, LOGSTORE, AND D6FS;
BLOCKSET IS PRESENT ONLY WHEN MULTI-MEMBER BLOCK MAPPING IS REQUIRED.  LPT,
ROOT SELECTION, AND MONITORFS DEVICE SETUP HAVE INITIALIZATION ENTRIES BUT NO
SEPARATE MRES PACKAGE.  BADMAP IS OPTIONAL.

EXACT KCORE/MRES FIGURES ARE BUILD MEASUREMENTS: REGENERATE THEM WITH
`MAKE PERMANENT-SIZE` AFTER MATERIAL KERNEL CHANGES INSTEAD OF TREATING AN OLD
MEASUREMENT AS A CURRENT LIMIT OR BASELINE.

## USERSPACE AND TOOLCHAIN

THE NORMAL BOOT ENTERS /SYSTEM/INIT AS PID 1.  INIT READS /CONFIG/INITTAB AND
STARTS LOGIN PROCESSES.  LOGIN AUTHENTICATES AGAINST /CONFIG/PASSWD AND EXECUTES
THE CONFIGURED SHELL, INITIALLY /SYSTEM/EXEC/DSH.

KCC IS THE REQUIRED NORMAL C COMPILER FOR BOTH KERNEL AND USERSPACE, AND
CURRENT NORMAL USERSPACE BUILDS WITH KCC/DAS.  THE RUN/EXEC
STARTUP ABI, DUP2-EQUIVALENT OPERATION, TTY LINE DISCIPLINE, ISATTY, UMASK, LOGIN
ENVIRONMENT, RECLAIMABLE D6FS CACHE, PDP-6 LPT SUPPORT, AND THE DIRECT-SLIDE
MM COMPACTOR/RELOCATOR ARE IMPLEMENTED.  MONITORFS IS CONSOLIDATED AT
/MONITOR; /PROC ALIASES /MONITOR/PROCESSES ONLY, AND /DEV PROJECTS DEVICE I/O
ENDPOINTS.  THE PRE-DSH FILESYSTEM/SYSCALL SET IS ALSO COMPLETE: SEEK, CHOWN,
CORRECT RMDIR SEMANTICS, AND D6FS MTIME/STAT/DATE/TOUCH SUPPORT ARE
IMPLEMENTED.  DSH IS THE INITIAL SHELL; SUBSTANTIAL DSH WORK REMAINS PAUSED
UNTIL THE COMPLETE PRE-USERLAND KERNEL/STORAGE GATE IN TODO.MD IS CLOSED.
AFTER THAT GATE, CONTINUE DSH, THEN THE REQUIRED CORE UTILITIES, MAKE,
DAS/DLINK/DARC, AND NATIVE KCC.

THE TTY LINE DISCIPLINE SITS BETWEEN TERMINAL DEVICES AND PROCESS READ/WRITE
CALLS.  COOKED MODE COLLECTS AND EDITS A LINE BEFORE DELIVERING IT, ECHOES
NORMAL INPUT, RECOGNIZES ERASE/KILL/EOF, AND CAN TURN CTRL-C/CTRL-Z INTO
FOREGROUND PROCESS-GROUP EVENTS.  RAW MODE DELIVERS INPUT DIRECTLY WITHOUT
LINE EDITING OR WAITING FOR A COMPLETE LINE, SO INTERACTIVE PROGRAMS CAN
HANDLE INDIVIDUAL KEYS THEMSELVES.

## FILESYSTEM AND STORAGE DIRECTION

D6FS OWNS OPTIONAL SWAP AND LOGSTORE LOGICAL RESERVATIONS.  THEY ARE NOT FILES;
VFS REGISTERS THEIR RAW BACKING RANGE AND ACTIVE I/O GOES DIRECTLY THROUGH THE
LOWER STORAGE PATH.  BLOCKSET OWNS ONLY LOGICAL-TO-PHYSICAL DISTRIBUTION, AND THE
OPTIONAL BADMAP LAYER APPLIES THE COMMON DISK/DRUM PHYSICAL EXCEPTION MAP BELOW
D6FS, LOGSTORE, AND SWAP.  BADMAP HANDLING IS OPTIONAL: INDIVIDUAL MEDIA MAY BE
CREATED WITHOUT A BADMAP, AND BADMAP SUPPORT MAY ALSO BE COMPILED OUT WITH
`KINIT_BADMAP=0`.  RESIDENT LOGSTORE- AND SWAP-SPECIFIC BLOCKSET OPERATIONS ARE
REMOVED.

THE EXTERNAL STATE NAMESPACE USES /MONITOR/PROCESSES AND /MONITOR/DEVICES.
/PROC IS AN EXACT VFS ALIAS OF /MONITOR/PROCESSES AND EXPOSES PROCESS OBJECTS
ONLY.  /DEV IS THE FLATTENED I/O VIEW: /DEV/NAME AND
/MONITOR/DEVICES/NAME/IO IDENTIFY THE SAME MONITORFS ENDPOINT.

THE 32K LOWMEM PROFILE IS NOT A SEPARATE OPERATING-SYSTEM VARIANT.  IT BUILDS
THE SAME DAIMOS SOURCES FOR A PDP-6 LIMITED TO 32K WORDS, USING A SMALLER
TRANSIENT KINIT INITIALIZATION PROFILE, AND THEN CONTINUES THROUGH THE NORMAL
INIT -> LOGIN -> DSH PATH.

LOADABLE/UNLOADABLE/RELOCATABLE MODULES AND USERSPACE OVERLAYS ARE NOT
IMPLEMENTED YET.

## FULL PDP-6 BOOT

`MAKE BOOT` BUILDS THE NORMAL PDP-6 CONFIGURATION WITH NATIVE, TENEX, AND ITS
DTFS PERSONALITIES PRESENT IN THE RESIDENT DTFS PACKAGE.  CTY IS LOCAL; THE SIMULATOR MAY EXPOSE
ADDITIONAL SERIAL TERMINAL LINES THROUGH HOST FACILITIES.  /CONFIG/INITTAB
STARTS THE CONFIGURED LOGIN PROCESSES.

DEVICE I/O NOW USES /DEV DIRECTLY; DEVICE STATUS/STATISTICS LIVE UNDER
/MONITOR/DEVICES.  NEW USERSPACE MUST USE THESE NAMES AND MUST NOT REINTRODUCE
THE REMOVED LEGACY DEVICE TREE.
