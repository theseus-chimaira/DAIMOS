# DAIMOS

DAIMOS IS A SMALL MULTIUSER OPERATING SYSTEM FOR THE 36-BIT PDP-6/PDP-10
FAMILY.  IT IS DESIGNED FIRST FOR THE PDP-6 AND ITS SEVERE MEMORY AND CPU
LIMITS, WHILE KEEPING MACHINE-DEPENDENT BOUNDARIES CLEAN ENOUGH FOR LATER
PDP-10 TARGETS.

THE PROJECT COMBINES IDEAS FROM EARLY TIME-SHARING SYSTEMS WITH A NEW KERNEL,
FILESYSTEM, USERSPACE, AND TOOLCHAIN DESIGNED SPECIFICALLY FOR THIS MACHINE
CLASS.  THE GOAL IS A PRACTICAL NATIVE SYSTEM WHICH CAN EVENTUALLY EDIT,
BUILD, LINK, INSTALL, AND RUN ITS OWN SOFTWARE.

FOR THE CURRENT ARCHITECTURE AND DEVELOPMENT STATE, READ `PROJECT-STATE.MD`.
OPEN WORK IS IN `TODO.MD`.  DETAILED DESIGN DOCUMENTATION LIVES IN THE
`PDP10-DOC` REPOSITORY.

## MINIMUM REQUIREMENTS AND SUPPORTED HARDWARE

THE PDP-6 IS THE CURRENT EXECUTABLE BASELINE.  DEVICE SUPPORT BELOW MEANS THAT
DAIMOS HAS A DRIVER OR SYSTEM INTERFACE FOR THE DEVICE CLASS; IT DOES NOT IMPLY
VALIDATION ON SURVIVING PHYSICAL HARDWARE.

| CATEGORY | MINIMUM REQUIREMENT | CURRENT PDP-6 SUPPORT |
| --- | --- | --- |
| CPU | PDP-6 | PDP-6 IS THE PRIMARY TARGET.  LATER PDP-10 MACHINE BACKENDS ARE PLANNED BEHIND THE SAME GENERIC KERNEL INTERFACES. |
| MEMORY | 32K 36-BIT WORDS | 32K LOW-MEMORY CONFIGURATION AND LARGER CORE SIZES. |
| CONSOLE | CTY | CONSOLE TERMINAL INPUT/OUTPUT AND GENERIC TTY LAYER. |
| CLOCK | APR LINE CLOCK | LINE-CLOCK SCHEDULER TICK; PCLK CALENDAR/TIME SUPPORT IS ALSO AVAILABLE. |
| ROOT / BLOCK STORAGE | ONE SUPPORTED ROOT MEDIUM | TYPE-270 DISK, DECTAPE, AND DRM236 DRUM ROOT PATHS. |
| DISK | OPTIONAL | TYPE-270 DISK, INCLUDING MULTI-MEMBER BLOCK SETS. |
| DRUM | OPTIONAL | TYPE-167/236 DRM236 DRUM FOR ROOT, SWAP, CACHE, MEMFS BACKING, AND LOGSTORE USE. |
| DECTAPE / MAGTAPE | OPTIONAL | DTC DECTAPE AND MTC MAGNETIC-TAPE INTERFACES; NATIVE DTFS/TSFS AND FOREIGN DECTAPE COMPATIBILITY SUPPORT. |
| TERMINALS | OPTIONAL | DCS AND GE COMMUNICATION TERMINALS THROUGH THE COMMON TTY LAYER. |
| PAPER TAPE | OPTIONAL | PTR READER AND PTP PUNCH. |
| PRINTER / CARDS | OPTIONAL | LPT LINE PRINTER, CARD READER, AND CARD PUNCH. |

| SLAVE INTERFACE | OPTIONAL | SLV INTERFACE. |

## EMULATOR TARGETS

NO SUITABLE PHYSICAL PDP-6 HARDWARE IS CURRENTLY AVAILABLE TO THE PROJECT, SO
DAIMOS DEVELOPMENT AND ACCEPTANCE TESTING TARGET EMULATORS.

SIMH PDP-6 IS THE CURRENT REFERENCE PLATFORM AND IS USED FOR BOOT, DEVICE,
FILESYSTEM, LOGIN, AND USERSPACE ACCEPTANCE TESTS.  `aap/pdp6` IS ALSO AN
INTENDED TARGET, BUT DAIMOS HAS NOT YET BEEN TESTED ON IT.  THE KERNEL AND
DRIVERS SHOULD NOT DEPEND ON EMULATOR-SPECIFIC BEHAVIOR WHEN THE ORIGINAL
HARDWARE INTERFACE CAN BE FOLLOWED INSTEAD.

## TOOLCHAIN

DAIMOS USES A PURPOSE-BUILT PDP-6/PDP-10 TOOLCHAIN RATHER THAN A HOST UNIX
COMPILER/ASSEMBLER/LINKER PIPELINE.  MOST TOOLS ARE ALSO INTENDED TO BECOME
NATIVE DAIMOS PROGRAMS AS SELF-HOSTING PROGRESSES.

| TOOL | PURPOSE |
| --- | --- |
| KCC | THE PRIMARY C COMPILER.  IT IS A HEAVILY MODIFIED PDP-10 KCC, EXTENDED AND TUNED FOR THE PDP-6 TARGET, THE DAIMOS ABI, MODERNIZED C SOURCE, AND EVENTUAL NATIVE SELF-HOSTING. |
| GCC | THE PDP-10 GCC PORT IS A SECOND COMPILER BACKEND USED FOR CODE-GENERATION COMPARISON, OPTIMIZER WORK, CROSS-CHECKING, AND RUNTIME SUPPORT WHERE REQUIRED.  IT IS NOT THE NORMAL DAIMOS SELF-HOSTING COMPILER. |
| DAS | THE DAIMOS ASSEMBLER.  IT ASSEMBLES PDP-6/PDP-10 SOURCE INTO THE DOBJ1 RELOCATABLE OBJECT FORMAT USED BY THE REST OF THE TOOLCHAIN. |
| DLINK | THE STATIC LINKER.  IT LINKS DOBJ1 OBJECTS AND DARC1 LIBRARIES INTO DXR EXECUTABLES, KERNEL IMAGES, AND MRES PACKAGES, AND PERFORMS DAIMOS-SPECIFIC LINK-TIME RELAXATION/FOLDING. |
| DARC | THE STATIC ARCHIVE/LIBRARY BUILDER FOR DARC1 OBJECT LIBRARIES. |
| PDP10-OBJDUMP | INSPECTS PDP-6/PDP-10 OBJECTS AND THEIR SYMBOL, SECTION, AND RELOCATION DATA. |
| P10FOLD | FINDS RELOCATION-SAFE DUPLICATE MACHINE CODE AND PRODUCES LINK-TIME FOLD PLANS USED TO REDUCE RESIDENT CODE SIZE. |
| P10SUPER | ANALYZES PDP-6/PDP-10 MACHINE CODE FOR PROVABLE PEEPHOLE IMPROVEMENTS AND SOURCE REORDERINGS WHICH CAN ENABLE ADDITIONAL FOLDING. |
| S6TEXT | CONVERTS HOST TEXT TO AND FROM DAIMOS SIXBIT/S6REC WORD TEXT. |
| MKD6FS / D6FSCK | CREATE, CHECK, AND REPAIR NATIVE D6FS FILESYSTEM IMAGES. |
| IMAGE/MEDIA TOOLS | BUILD DSK270, DECTAPE, MAGNETIC-TAPE, PAPER-TAPE, BOOT-STREAM, LOGSTORE, SWAP, AND OTHER HOST-SIDE MEDIA FORMATS USED TO BOOT AND TEST DAIMOS. |

THE TOOLCHAIN USES DOBJ1 RELOCATABLE OBJECTS, DARC1 STATIC LIBRARIES, AND DXR
EXECUTABLES.  HOST-SIDE TOOLS ARE PART OF THIS TREE UNDER `TOOLS/HOST`; THE
BOUNDED NATIVE DARC/DLINK/OBJDUMP IMPLEMENTATIONS LIVE UNDER
`USERLAND/TOOLCHAIN`.  TOOLCHAIN AND TARGET REGRESSIONS LIVE IN THE PDP10 AND
DAIMOS TESTKITS.

## PLANNED 0.9 USERSPACE

DAIMOS 0.9 IS INTENDED TO BE A USABLE MULTIUSER DEVELOPMENT SYSTEM, NOT JUST A
KERNEL DEMONSTRATION.  THE USERSPACE TARGET INCLUDES:

- **DSH**, A NATIVE KSH-INSPIRED SHELL WITH SCRIPTS, VARIABLES, FUNCTIONS,
  REDIRECTION, CONCURRENT PIPELINES, PROCESS-GROUP JOB CONTROL, GLOBBING,
  PROFILES, COMMAND COMPLETION, AND A BOUNDED INTERACTIVE LINE EDITOR.
- A SMALL BUT PRACTICAL **CORE UTILITY SET** FOR FILE MANAGEMENT, TEXT
  PROCESSING, SYSTEM ADMINISTRATION, PROCESS/DEVICE INSPECTION, AND BUILD
  SCRIPTS.  THE INTENTION IS TO PORT THE USEFUL BEHAVIOR, NOT TO CLONE AN
  ENTIRE MODERN UNIX COREUTILS INSTALLATION.
- **ED** AS A SMALL EMERGENCY EDITOR AND **ELVIS VI/EX** AS THE NORMAL NATIVE
  SOURCE EDITOR, INCLUDING SPELLING AND FOLDING SUPPORT BUT WITHOUT COLOR,
  SYNTAX-HIGHLIGHTING, OR URL FEATURES.
- **MAKE** AND THE NATIVE BUILD TOOLS: DAS, DLINK, DARC, OBJECT INSPECTION, AND
  THE SUPPORTING TEXT/FILE UTILITIES NEEDED BY REAL BUILDS.
- A NATIVE **C DEVELOPMENT ENVIRONMENT**: KCC/CPP, LIBC, CRT0, LIBSYS, STATIC
  LIBRARIES, AND ENOUGH BUILD INFRASTRUCTURE TO REBUILD USERSPACE AND THEN THE
  DAIMOS KERNEL ON DAIMOS ITSELF.
- SYSTEM ADMINISTRATION TOOLS BUILT AROUND THE NORMAL VFS AND MONITORFS
  INTERFACES RATHER THAN PRIVATE KERNEL DEBUG ABIS.

THE FIRST SELF-HOSTING MILESTONE IS REACHED WHEN DAIMOS CAN EDIT OR IMPORT
SOURCE, RUN DSH AND MAKE, BUILD WITH NATIVE KCC+DAS+DLINK+DARC, AND INSTALL THE
RESULT.  USERSPACE OVERLAYS ARE TO BE CONSIDERED ONLY AFTER REAL NATIVE
DSH/MAKE/ASSEMBLER/LINKER/EDITOR/COMPILER WORKING SETS HAVE BEEN MEASURED.

## CORE DESIGN

DAIMOS IS SMALL, BUT IT IS NOT A SINGLE-PROCESS MONITOR.  THE CURRENT KERNEL
DESIGN INCLUDES THE FOLLOWING MAJOR FACILITIES:

- A NATIVE MULTIUSER **PROCESS MODEL** WITH RUN/EXEC/WAIT, CREDENTIALS,
  PROCESS HIERARCHY, SESSIONS, PROCESS GROUPS, CONTROLLING TERMINALS,
  STOP/CONTINUE, PROCESS EVENTS, AND A SMALL REAL-TIME SCHEDULING EXTENSION.
- A PDP-6 **MEMORY MANAGER** WITH RELOCATION, COMPACTION, PINNING, PROCESS
  SWAPPING, AND A GENERIC VM BOUNDARY SO PAGED PDP-10 MACHINES CAN LATER USE A
  DIFFERENT BACKEND WITHOUT REPLACING THE PROCESS MODEL.
- A COMMON **VFS** WITH FILE DESCRIPTORS, PATH LOOKUP, MOUNTS, PERMISSIONS,
  OWNERSHIP, LINKS, STAT DATA, AND WORD-STREAM I/O.
- **D6FS** AS THE NATIVE WRITABLE FILESYSTEM, **MEMFS** FOR VOLATILE FILES,
  AND **DTFS/TSFS** FOR DECTAPE, INCLUDING ITS/TENEX MEDIA COMPATIBILITY WHERE
  APPROPRIATE.
- **MONITORFS** AS THE STRUCTURED PROCESS, DOMAIN, MEMORY, AND DEVICE STATE
  NAMESPACE, WITH `/DEV` PROVIDING THE NORMAL DEVICE-I/O VIEW.
- NATIVE 36-BIT **WORD PIPES AND FIFOS**.  TEXT, BYTE, PAPER-TAPE, CARD, AND
  DEVICE FORMATS ARE FRAMED AT THEIR OWN BOUNDARIES RATHER THAN INSIDE IPC.
- A SIXBIT/S6REC **TEXT MODEL** FOR NATIVE TEXTUAL DATA AND RECORD-ORIENTED
  INTERFACES.  REGULAR FILES REMAIN ORDINARY 36-BIT WORD STREAMS; RAW TERMINAL
  I/O REMAINS CHARACTER-ORIENTED.
- A LAYERED **STORAGE SYSTEM** WITH LOGICAL BLOCK SETS, OPTIONAL BAD-MEDIA
  REMAPPING, DEVICE-SPECIFIC MECHANICAL SCHEDULING, A SHARED BLOCK CACHE,
  SWAP/MEMFS BACKING STORE, AND AN INDEPENDENT LOGSTORE.
- ASYNCHRONOUS DEVICE I/O FROM THE PROCESS POINT OF VIEW, WITH SUPPORT FOR
  DISK, DRUM, DECTAPE/MAGTAPE, TERMINALS, PAPER TAPE, CARDS, PRINTERS, AND
  DISPLAY DEVICES.
- A TWO-STAGE **BOOT AND INITIALIZATION PATH** IN WHICH TRANSIENT KINIT CODE
  DISCOVERS HARDWARE, SELECTS/MOUNTS THE ROOT FILESYSTEM, INSTALLS ONLY THE
  REQUIRED RESIDENT SERVICES, AND STARTS USERSPACE INIT/LOGIN.
- COMPACT **MINIT/MRES MODULE STRUCTURE**: HARDWARE DISCOVERY AND SETUP MAY BE
  TRANSIENT WHILE ONLY THE SMALL RUNTIME SERVICE PACKAGE REMAINS RESIDENT.
  GENERAL RUNTIME LOADABLE/UNLOADABLE MODULES ARE DELIBERATELY DEFERRED UNTIL
  AFTER USERSPACE OVERLAY REQUIREMENTS ARE KNOWN.
- D6LZ-BASED **COMPRESSION SUPPORT** FOR SPACE-EFFICIENT SYSTEM IMAGES AND
  STORAGE PATHS WHERE THE CPU/I/O TRADEOFF IS BENEFICIAL.

THE IMPLEMENTATION IS AGGRESSIVELY SIZE-CONSCIOUS BECAUSE THE 32K PDP-6 IS A
REAL DESIGN TARGET, BUT SIZE OPTIMIZATION IS KEPT BELOW CORRECTNESS, CLEAR
INTERFACES, AND MAINTAINABLE MACHINE-INDEPENDENT BOUNDARIES.
