## SOURCE LAYOUT

## KERNEL

THE KERNEL HAS A SMALL PERMANENT KCORE AND RECLAIMABLE KINIT REGIONS.  FIRST-USER BOOTSTRAP CODE IS RECLAIMED RATHER THAN RETAINED AS A PERMANENT DISPOSAL TRAMPOLINE.

THE PROCESS DESCRIPTOR IS 3 WORDS.  PROCESS TABLE SIZE IS SELECTED FROM 64, 128, OR 256 SLOTS ACCORDING TO AVAILABLE CORE.  256 IS THE ARCHITECTURAL SLOT LIMIT.  PID IS DERIVED FROM THE PROCESS-TABLE SLOT AND IS NOT STORED REDUNDANTLY IN THE DESCRIPTOR; THE LOW EIGHT BITS OF PROC.META ARE CURRENTLY FREE.

EACH ACTIVE PROCESS USES A STABLE 0420 OCTAL WORD EXECUTIVE AREA, 272 DECIMAL WORDS.  THE FIXED CONTEXT OCCUPIES 0000 THROUGH 0044, CWD IS 0045, THE 13 TWO-WORD FILE DESCRIPTORS OCCUPY 0046 THROUGH 0077, AND THE PRIVATE KERNEL STACK OCCUPIES 0100 THROUGH 0417.  THE PRIVATE STACK REMAINS 0320 OCTAL WORDS, 208 DECIMAL WORDS.  THE USER EXTENT MAY MOVE OR SWAP WHILE THE EXECUTIVE AREA REMAINS RESIDENT.

FILE DESCRIPTORS PRESERVE A FULL 36-BIT CHARACTER OFFSET.  THE OTHER WORD PACKS THE CANONICAL VNODE WITH READ/WRITE/DIRECTORY, DUP/LOCK-FAMILY, AND REGULAR/LOCK STATE IN NINE BITS GUARANTEED ZERO BY THE CURRENT VNODE FIELD RANGES.  FILE_NEW_FD REJECTS A VNODE WHICH USES THOSE RESERVED BITS.  THIS SAVES 13 WORDS PER ACTIVE PROCESS AT A FIXED KCORE COST OF 8 WORDS, FOR NET PHYSICAL SAVINGS OF 5 WORDS AT ONE ACTIVE PROCESS AND 57 WORDS AT FIVE.

THE SEPARATE PINNED RUNTIME IDLE/EXIT KERNEL STACK IS 0100 OCTAL WORDS, 64 DECIMAL WORDS.  LATE KINIT NOW REMAINS ON ITS DISPOSABLE KINIT RESERVE STACK UNTIL ALL ALLOCATING/VFS BOOT WORK IS COMPLETE, THEN PUBLISHES THE PERMANENT IDLE STACK IMMEDIATELY BEFORE THE NO-RETURN USER TRANSITION.  TEST-ONLY WATERMARKING MEASURES 025 OCTAL WORDS, 21 DECIMAL, AT THE FINAL-PROCESS EXIT PATH; ORDINARY IDLE/SCHEDULER USE IS SMALLER.  THE TEST LIMIT IS 0060 OCTAL WORDS.  COMPARED WITH THE PREVIOUS ACCEPTED 0500-OCTAL STACK THIS SAVES AN ADDITIONAL 0400 OCTAL WORDS, 256 DECIMAL, OF PERMANENT RESIDENT RAM; COMPARED WITH THE ORIGINAL 02000-OCTAL ALLOCATION THE TOTAL SAVING IS 01700 OCTAL WORDS, 960 DECIMAL.

THE SCHEDULER SUPPORTS RUNNING, SLEEPING, STOPPED, AND ZOMBIE PROCESS STATES, EVENT WAITING, NICE VALUES, CPU PENALTY, SLEEP AGING, CLOCK PREEMPTION, AND SOFTWARE RESCHEDULING.

GENERAL PROCESS CREATION AND UNIX-STYLE PIPES ARE NOT PRESENT YET.

## MEMORY MANAGEMENT

THE MEMORY MANAGER TRACKS AT MOST 32 EXTENTS WITH 2 WORD EXTENT DESCRIPTORS.

PROCESS AND MOVABLE MODULE EXTENTS CAN BE COMPACTED.  COMMON PDP-6 BLT COPY AND ZERO PATHS ARE USED FOR MOVEMENT AND INITIALIZATION.

PERMANENT MM TELEMETRY COUNTERS FOR COMPACTIONS, WORDS MOVED, AND ALLOCATION FAILURES ARE NOT PART OF MEMORY-MANAGER STATE.

## SWAP

PROCESS SWAPPING USES ONE RESIDENT WORD PER LOGICAL PROCESS SLOT.  WHILE A PROCESS IS RESIDENT, THAT WORD PACKS THE EXECUTABLE PROVIDER, MOUNT, FILE INDEX, AND PURE-TEXT BOUNDARY.  WHILE THE PROCESS IS SWAPPED, THE SAME WORD HOLDS THE PACKED FIRST SWAP BLOCK AND TOTAL BLOCK COUNT.

THE RESIDENT EXECUTABLE PACKING IS LOSSLESS FOR THE CURRENT EXECUTABLE-CAPABLE MEMFS, DTFS, AND D6FS PROVIDERS: PROVIDER-4 USES 2 BITS, MOUNT-ID-1 USES 2 BITS, FILE INDEX USES 18 BITS, AND THE PURE-TEXT BOUNDARY USES 14 BITS.  LOCAL FILE KIND IS IMPLIED BY THE PROVIDER.

ON SWAP-OUT, ONE HEADER BLOCK SAVES THE RESIDENT PACKED WORD ON DISK BEFORE THE NON-RECONSTRUCTIBLE PROCESS DATA.  SWAP-IN RESTORES THAT WORD AND RELOADS KNOWN CLEAN PURE TEXT FROM THE EXECUTABLE BACKING FILE.  A ZERO TEXT BOUNDARY CONSERVATIVELY SWAPS THE COMPLETE PROCESS IMAGE.

COMPARED WITH THE PREVIOUS THREE-WORD TABLE, THIS REMOVES TWO PER-SLOT RESIDENT WORDS.  THE SMALL RESIDENT HEADER/UNPACK PATH ADDS 54 FIXED KCORE WORDS, GIVING NET RESIDENT SAVINGS OF 74 WORDS AT 64 SLOTS, 202 WORDS AT 128 SLOTS, AND 458 WORDS AT 256 SLOTS.  THE COST IS ONE EXTRA 0200-OCTAL-WORD DISK BLOCK FOR EACH PROCESS WHILE IT IS ACTUALLY SWAPPED.

SWAP KEEPS ONE LIVE WORD FOR USED SWAP BLOCKS.  TOTAL BLOCKS COME FROM THE DISKSET CONFIGURATION AND FREE BLOCKS ARE DERIVED AS TOTAL MINUS USED.

THE D6SET SWAP STATUS FILE REPORTS THREE 12-DIGIT OCTAL VALUES:

1. TOTAL SWAP BLOCKS.
2. USED SWAP BLOCKS.
3. FREE SWAP BLOCKS.

SWAP NO LONGER MAINTAINS CUMULATIVE READ REQUEST, WRITE REQUEST, BLOCKS READ, BLOCKS WRITTEN, OR SWAP ERROR COUNTERS.  STORAGE ERRORS REMAIN VISIBLE THROUGH D6SET DEVICE ACCOUNTING.

SWAP-SPECIFIC PERMANENT ACCOUNTING STATE IS 1 WORD: LIVE USED BLOCKS.

## FILESYSTEM AND STORAGE

VFS PROVIDES COMMON FILESYSTEM DISPATCH.

D6FS IS PRESENT AS A NORMAL WRITABLE FILESYSTEM.

DTFS SUPPORT IS PRESENT WITH BUILD-TIME NATIVE, TENEX, AND ITS PERSONALITY SUPPORT.

D6SET PROVIDES AGGREGATE STORAGE ACCESS, SWAP TAILS, AND LOGSTORE REGIONS.  TRANSFER AND SERVICE PATHS HAVE BEEN CONSOLIDATED TO REDUCE DUPLICATED RESIDENT CODE.

## UUO AND SERVICE ABI

USER MONITOR UUOS OCCUPY 040 THROUGH 073.  074 THROUGH 077 ARE RESERVED FOR EXTENSION.  UUO 043 IS THE BULK WRITE_CHARS CONSOLE OUTPUT CALL.

LIBC PROVIDES DIRECT USER UUO VENEERS.  ARGUMENT ZERO IS PASSED THROUGH THE UUO EFFECTIVE ADDRESS AND THE REMAINING C ARGUMENTS USE REGISTERS.

EXECUTIVE INTERNAL FILESYSTEM SERVICES USE A DIRECT REGISTER BRIDGE.  EXECUTIVE PRIVATE UUO TRAPS WERE REMOVED SO INTERNAL PROVIDER DISPATCH DOES NOT PAY A SECOND HARDWARE TRAP.

DISKSET RUNTIME SERVICE CALLS USE A REGISTER ABI INSTEAD OF BUILDING A 4 WORD REQUEST STRUCTURE AT EACH CALL SITE.

## MODULE RUNTIME

RUNTIME MODULE DESCRIPTORS ARE PACKED TO 1 WORD EACH.  INITIALIZED LENGTH AND CURRENT BASE SHARE THE DESCRIPTOR WORD.

MM REMAINS AUTHORITATIVE FOR THE FULL MOVABLE EXTENT.  RELOCATION MAP SIZE IS DERIVED.

DYNAMIC BINDINGS ARE ZERO TERMINATED, SO A SEPARATE BINDING COUNT IS NOT KEPT.  MODULE MOVE ENABLE STATE REUSES DESCRIPTOR SLOT ZERO.

BOOT-TIME MODULE INITIALIZATION EXISTS.  THE GENERAL RUNTIME LOAD AND UNLOAD INTERFACE IS NOT IMPLEMENTED YET.

## USER ENVIRONMENT

USR CONTAINS ONE LIBC TREE, DSH, AND SHARED COMMAND IMPLEMENTATIONS.

LIBC CONTAINS CRT STARTUP, UUO SYSTEM CALL VENEERS, COMMON USER SUPPORT, AND PDP-10 MEMCPY AND MEMMOVE ASSEMBLY.

DSH CAN USE THE EXISTING FILE AND COMMAND INTERFACES.  PIPELINES CANNOT BE COMPLETE UNTIL KERNEL PIPES AND PROCESS CREATION ARE IMPLEMENTED.

MAKE, DAS, AND KCC ARE NOT YET PART OF THE DAIMOS NATIVE USER ENVIRONMENT.

PROCESS PRIVATE KERNEL STACK WATERMARKING IS AVAILABLE AS A TEST-ONLY BUILD OPTION.  THE 0320-OCTAL-WORD STACK REACHED 0303 OCTAL WORDS UNDER CURRENT DSH/VFS/FILE WORKLOADS, LEAVING ONLY 0015 OCTAL WORDS OF OBSERVED HEADROOM.  THE SEPARATE PERMANENT IDLE/EXIT STACK ALSO HAS TEST-ONLY WATERMARKING; WITH LATE KINIT KEPT ON ITS DISPOSABLE RESERVE IT REACHES 025 OCTAL WORDS AGAINST A 0060 TEST LIMIT AND 0100-OCTAL PRODUCTION ALLOCATION.  PRODUCTION BUILDS CONTAIN NO WATERMARK CODE OR STATE.

## FULL PDP-6 BOOT AND PERMANENT SIZE

THE STANDARD `MAKE BOOT` PDP-6 DISK CONFIGURATION NOW ENABLES EVERY IMPLEMENTED
SIMH DEVICE, BUILDS NATIVE/TENEX/ITS DTFS SUPPORT, ATTACHES THREE WRITABLE
DECTAPES AND TWO WRITABLE MAGTAPES, AND PRE-CREATES /MOUNT/DT0 THROUGH
/MOUNT/DT2.  DSH ACCEPTS MOUNT AS THE NORMAL DTFS MOUNT COMMAND WHILE RETAINING
MOUNT.DTFS AS A COMPATIBILITY SPELLING.

THE CURRENT FULL BUILD HAS 6081 DECIMAL WORDS, 013701 OCTAL WORDS, OF FIXED
KCORE AND 6032 DECIMAL WORDS, 013620 OCTAL WORDS, OF INSTALLED MRES PACKAGES.
KCORE + ALL FULL-BOOT MRES IS THEREFORE EXACTLY 12113 DECIMAL WORDS, 027521
OCTAL WORDS.  THIS EXCLUDES KINIT/INIT AND PROCESS-PRIVATE STORAGE.  THE HARD
PRE-USERLAND TARGET IS BELOW 11500 DECIMAL WORDS SO LATER SYSCALL AND PROCESS
WORK HAS RESIDENT HEADROOM.  `MAKE PERMANENT-SIZE` UNDER
SYSTEM/BOOT/PDP6-DISK REPRODUCES THE COMPONENT BREAKDOWN.

D6FS FCB STRUCTURAL VALIDATION USES A HAND-WRITTEN PDP-10 IMPLEMENTATION IN
D6FS_VALIDATE_PDP10.S; THE HOST C IMPLEMENTATION REMAINS THE REFERENCE FOR
HOST-SIDE TOOLS AND TESTS.  THIS SELECTIVE ASSEMBLY CHANGE REDUCES D6FS MRES
FROM 2124 TO 2095 DECIMAL WORDS WITHOUT CHANGING THE ON-DISK FCB FORMAT.

DTFS BLOCK-HEADER ENCODE/DECODE OPERATIONS ARE EXPRESSION-LEVEL FIELD
OPERATIONS RATHER THAN OUT-OF-LINE C HELPERS.  THIS LETS THE PDP-10 COMPILER
EMIT LDB/SHIFT-OR OPERATIONS AT EACH USE SITE AND REDUCES DTFS MRES FROM 2159
TO 2137 DECIMAL WORDS.

D6FS DIRECTORY-ENTRY WRITES USE A BOUNDED HAND-WRITTEN PDP-10 ROUTINE WHILE
THE HOST C IMPLEMENTATION REMAINS AVAILABLE FOR HOST BUILDS.  THE TARGET
ROUTINE RETAINS DIRECTORY/IMMUTABLE CHECKS, RESIZE-ON-GROW, AND THE SIX-WORD
ON-DISK ENTRY FORMAT, AND REDUCES D6FS MRES FROM 2095 TO 2068 DECIMAL WORDS.  THE SAME TARGET FILE ALSO
IMPLEMENTS THE FREE-FCB LINEAR SCAN WITHOUT GCC UNSIGNED-COMPARE NORMALIZATION.
